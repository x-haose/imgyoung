# Contributing

Thanks for helping with ImgYoung. This document covers the development setup, what "done" means for a change, and how to submit it. The design rationale lives on the documentation site: the [Architecture](https://imgyoung.x-haose.com/en/docs/architecture) page gives the overview and technology choices, and each feature page covers behavior and trade-offs (sources in `docs/content/docs`). Change the relevant page first when a change touches the design. Day-to-day conventions are in [AGENTS.md](./AGENTS.md).

## Environment

| Tool | Version | Purpose |
|---|---|---|
| Go | the version in `go.mod` | server; build, test and lint always run with `CGO_ENABLED=0` and `-tags nodynamic` (set through `GOFLAGS` by the Taskfile and CI; without it the webp library makes the linux binary depend on the system dynamic linker and the image cannot start). The one exception is the race detector in `task test`: on Linux and Windows it needs cgo and a C compiler, and the Taskfile turns cgo on for it |
| Node.js + pnpm | Node 22; the pnpm version is in `packageManager` of `web/package.json` (`corepack enable` is enough) | admin console |
| [Task](https://taskfile.dev) | 3 | development entry point, `task --list` shows every task |
| golangci-lint | the version pinned in `.github/workflows/ci.yml` | Go lint gate |
| ShellCheck | any recent version | lint for the install script `install.sh` |
| sqlc, atlas | any recent version | only needed when changing the database schema or queries |

```bash
task web            # install front-end dependencies and build the bundle (go:embed needs web/dist)
task run            # run locally, listening on :8721 by default
cd web && pnpm dev  # front-end hot reload; /api and image paths are proxied to 8721
```

## Repository layout

- `cmd/imgyoung` composition root; `internal/core` business logic; `internal/infra` infrastructure; `internal/http` HTTP inbound; `store/` the public storage engine; `web/` admin console; `e2e/` end-to-end tests; `api/openapi.yaml` API reference.
- Dependencies flow http → core → {infra, store}; store imports nothing under `internal`. depguard enforces this in lint.

## When is a change done

1. Go: `goimports -w .`, `golangci-lint run` reports 0 issues, `go test -race ./...` passes; run `task e2e` for anything that changes externally visible behaviour.
2. Front end: `cd web && pnpm lint && pnpm build`, both clean.
3. Changed an HTTP endpoint: update `api/openapi.yaml` in the same change. The e2e suite validates every response against it; the front-end types are generated by `pnpm gen:api` (run automatically by `pnpm build`), and the generated `web/src/lib/api.gen.ts` is committed with the change.
4. Changed the database: `internal/infra/db/schema/` is the single source of truth; `atlas migrate diff <name> --env local` generates the migration and `task generate` regenerates the sqlc code.
5. Changed the design or user-visible behavior: update the relevant documentation page (`docs/content/docs`, both Chinese and English) before the code, and make sure `cd docs && pnpm lint && pnpm build` passes.

## Code conventions (summary)

- Every declaration is commented: functions in goanno format (first line starts with the identifier), struct fields with a trailing comment; describe the current state only, never history or discussion.
- Files < 800 lines, functions < 50 lines (test functions excepted), nesting ≤ 4, cognitive complexity ≤ 15, lines ≤ 120 characters; lint enforces all of it.
- Errors are propagated, never swallowed; no `//nolint` or similar suppression comments: fix the code, and exclude a genuine false positive in `.golangci.yml` by file and rule, with the reason.
- Only two kinds of tests: pure computation, and tests against a real database / storage / queue. Flows are covered end to end, not with fakes.
- Chinese punctuation: Markdown documents, OpenAPI descriptions and the UI dictionaries use full-width punctuation; code comments, logs, server-side messages and commit messages use half-width.
- Front end: all copy goes through the i18n dictionaries (Simplified Chinese is the baseline, English is type-checked against it); route files do not import zod; requests only go through `web/src/lib/api.ts` and server state only through TanStack Query.

## Commits and pull requests

- Commit messages are `<type>: <description>` with type one of feat / fix / refactor / docs / test / chore / perf / ci, optionally scoped, e.g. `feat(渠道): …`; the description says what changed and why.
- One pull request does one thing; its description states the change, the reason and how it was verified. A red CI does not get merged.

## Releases

Pushing a `vX.Y.Z` tag triggers the release workflow: goreleaser builds amd64 and arm64 binaries for linux / darwin / windows and a multi-arch GHCR image, and generates release notes grouped by commit type. Validate the configuration locally with `goreleaser check`.

## Security issues

Please do not open a public issue for a security vulnerability; report it privately through a Security Advisory on the repository's Security page.
