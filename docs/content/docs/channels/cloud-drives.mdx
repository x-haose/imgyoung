## 支持的网盘

「新建渠道」选类型时，「网盘」分组里除了通用 [WebDAV](./object-storage.mdx) 之外，还有 6 个需要 OAuth 授权的模板：

| 模板 | rclone 后端 | 专属字段 |
|---|---|---|
| OneDrive | `onedrive` | 区域 |
| Google Drive | `drive` | — |
| Dropbox | `dropbox` | — |
| pCloud | `pcloud` | 数据区域 |
| Box | `box` | — |
| Yandex Disk | `yandex` | — |

专属字段之后，6 个模板依次是「应用 Client ID」「应用 Client Secret」「授权」「存储目录」：

- **区域**（OneDrive）：「国际版」「美国政府云」「德国云」「中国世纪互联」。它决定授权与接口的端点，要与账号所属的区域一致。
- **数据区域**（pCloud）：「美国」或「欧洲」，要与注册账号时所选的区域一致，否则换取令牌会失败。
- **应用 Client ID / 应用 Client Secret**：你在服务商开放平台自建的 OAuth 应用的标识与密钥。令牌续期用的就是这两项，所以必须与签发令牌的应用一致：
  - 一键授权必须先填 Client ID；
  - 粘贴的令牌如果是用自建应用取得的，也要填这两栏；用 rclone 内置应用取得的，两栏留空。

  两者随渠道配置加密保存，编辑时显示为掩码。
- **授权**：令牌，用下面两种授权方式之一填入。未授权不能保存。
- **存储目录**：网盘里存放图片的目录，默认提示 `imgyoung`；留空则存放在根目录。

授权所需的端点、权限范围和 rclone 内置应用的标识，都取自 rclone 后端自身的注册信息，ImgYoung 没有为各家服务商单独编写代码。

**OneDrive 的驱动器**：拿到新的授权后，保存或测试连接时，ImgYoung 按 rclone 自身的配置流程走完授权之后的步骤，每一步都取默认答案：选定账号的默认驱动器，写下 `drive_id` 与 `drive_type`。结果与 `rclone config` 全部取默认值时相同。向服务商查询驱动器失败时，保存返回 400，测试连接显示原因。编辑时沿用已存的授权，不会重新选择驱动器。要用 SharePoint 文档库或其他驱动器，见[OneDrive 的其他驱动器](#onedrive-的其他驱动器)。

**pCloud 的令牌**：pCloud 的令牌永不过期（到期时刻为零值），也不带刷新令牌，可以照常保存。

## 授权方式一：粘贴令牌

在任意一台有浏览器的电脑上用 rclone 取得令牌，再粘贴到表单里。这种方式不要求 ImgYoung 所在的服务器有公网域名，没有域名的部署只能用它。

<Steps>
<Step>
在有浏览器的电脑上安装 rclone，执行表单里提示的命令（以 Google Drive 为例）：

```bash title="终端"
rclone authorize "drive"
```

浏览器会打开服务商的登录与授权页，在那里完成授权。
</Step>
<Step>
终端输出形如：

```text
Paste the following into your remote machine --->
{"access_token":"…","token_type":"Bearer","refresh_token":"…","expiry":"…"}
<---End paste
```

把两行标记之间的内容整段复制。
</Step>
<Step>
在表单的「授权」一栏切到「粘贴令牌」，粘贴进去，填好其余字段，点「测试连接」后保存。
</Step>
</Steps>

- 令牌 JSON 和 rclone 编码后的配置串（`rclone authorize` 带配置串参数时的输出）都能识别，ImgYoung 会从中取出令牌。
- 会过期的令牌必须带刷新令牌，否则访问令牌过期后无法续期，保存会被拒绝。永不过期的令牌（如 pCloud）不需要刷新令牌。
- `rclone authorize "<后端名>"` 取得的令牌由 rclone 内置应用签发，「应用 Client ID」「应用 Client Secret」留空，续期时 rclone 同样用内置应用。
- 要用自建应用，执行 `rclone authorize "<后端名>" <Client ID> <Client Secret>`，再把同一个应用的 Client ID 与 Client Secret 填进表单。自建应用要登记 rclone 的本机回调地址 `http://127.0.0.1:53682/`。

## 授权方式二：后台一键授权

在后台直接走完 OAuth 授权码流程。这种方式必须用自建应用：OAuth 的回调地址要事先在服务商处登记，而 rclone 内置应用登记的只有本机回环地址，浏览器无法经它回调到远程服务器。

<Steps>
<Step>
在「设置 → 运行配置 → 访问与链接 → 对外站点地址」填好 ImgYoung 的对外地址，如 `https://img.example.com`。没有填写时无法发起授权。
</Step>
<Step>
到服务商的开放平台创建应用，把回调地址登记为对外站点地址加固定路径：

```text
https://img.example.com/api/admin/channel-oauth/callback
```

两边必须逐字符一致，协议、域名、端口、路径都算在内。
</Step>
<Step>
在表单「授权」一栏上方的「应用 Client ID」「应用 Client Secret」里填好自建应用的凭证，再在「授权」一栏的「一键授权」里点「前往授权 …」。没填 Client ID 时这个按钮不可用。浏览器会新开一个页面，进入服务商的授权页。
</Step>
<Step>
授权完成后，回调页显示 `授权成功,请回到后台继续。`，表单的「授权」一栏变为「已授权」，保存即可。回调页按浏览器的 `Accept-Language` 显示中文或英文。
</Step>
</Steps>

- 回调接口要求管理员登录，授权要在**已登录后台的同一个浏览器**里完成。
- 一次授权会话 10 分钟内有效，表单最多等待约 11 分钟，超时提示「等待授权超时，请重新发起」。
- 令牌不写进回调页面，由表单凭一次性标识领取，只能领取一次。
- 换取令牌失败时，表单显示「换取令牌失败，请核对应用凭证与回调地址」。在服务商页面拒绝或取消授权时，显示「授权被拒绝或取消：」加服务商返回的原因。
- 编辑已有渠道时重新授权，应用凭证两栏保持掩码即沿用已存的值。清理中的渠道不能重新授权。
- Client ID 与 Client Secret 随渠道保存，令牌到期后 rclone 用同一个应用续期。

## 令牌的续期与保存

访问令牌临近过期时，rclone 会自己刷新它，并把新令牌写回。ImgYoung 随即用主密钥加密，存进渠道配置。rclone 在运行中写回的其他参数也这样保存。

- **只有一个刷新者**：ImgYoung 不另外定时刷新令牌。有些服务商每次刷新都会作废旧的刷新令牌，两方各自刷新会互相作废对方的令牌。周期轻探测（默认每 60 秒）发出的只读请求，足以让 rclone 按时刷新。
- **写回失败**：新令牌没能写进元数据库时，只记一条日志 `后端写回参数无法落库`。驱动继续使用手里的新令牌，下一次写回时再保存；在那之前重启进程，会退回元数据库里的旧令牌。
- **与编辑同时发生**：重新授权换了令牌之后，旧驱动刷新出的令牌不会覆盖新令牌。编辑只改了别的参数（优先级、存储目录等）、令牌保持掩码时，刷新出的令牌照常保存。编辑保存期间恰好发生令牌刷新时，这次保存返回 409（错误码 `channel_config_changed`），重新保存即可，见[编辑渠道](./index.mdx#保存冲突)。

编辑网盘渠道时，「授权」一栏显示「已授权 · 沿用已存令牌」：保持不动即沿用，点「重新授权」可以换一个令牌。

### 测试连接与保存时的令牌刷新

测试连接或保存渠道时，ImgYoung 会临时构造一个后端，服务商可能在这时刷新令牌。新令牌不会丢失：

| 时机 | 被刷新的令牌 | 新令牌的去向 |
|---|---|---|
| 保存成功 | 任意 | 随配置一起保存 |
| 保存失败 | 表单里提交的令牌（新建渠道，或编辑时新授权、新粘贴的令牌）| 随错误响应的 `token` 字段交还表单，并提示「保存失败，但服务商在保存期间刷新了授权令牌。表单已换用新令牌，改正后再次保存即可，无需重新授权。」|
| 保存失败 | 编辑时沿用的已存令牌 | 直接写回渠道并重新装载，不随错误返回；写回不成时同样交还表单 |
| 测试连接 | 编辑时沿用的已存令牌（「授权」一栏保持「已授权 · 沿用已存令牌」）| 直接写回渠道；写回不成时同样交还表单 |
| 测试连接（通过或失败）| 表单里提交的令牌 | 交还表单：测试结果下方提示「测试期间服务商刷新了授权令牌，表单已换用新令牌，直接保存即可；原令牌可能已失效。」，「授权」一栏显示「已授权」，之后保存提交的就是新令牌 |

自定义模式下，交还表单的新令牌写在后端参数的 `token` 一行。

<Callout type="warn" title="导出的配置文件里也有令牌">
[导出的 rclone 配置文件](./encryption.mdx#用导出的配置文件)里带着令牌。ImgYoung 仍在使用该渠道时，不要用这个文件：Box 这类服务商的刷新令牌只能用一次，两边会互相作废对方的令牌。ImgYoung 刷新令牌之后，文件里的令牌就过时了，需要重新导出。
</Callout>

## OneDrive 的其他驱动器

模板只会选定账号的默认驱动器。要用 SharePoint 文档库或其他驱动器，在「新建渠道 → 高级 → 自定义」里手填 `drive_id` 与 `drive_type`。

先在有浏览器的电脑上用 `rclone config` 交互式地新建一个 OneDrive remote，在选择驱动器的步骤里选中目标驱动器，再查看它写下的参数：

```bash title="终端"
rclone config
rclone config show onedrive-tmp
```

把输出里的值填进自定义表单：

| 键 | 值 |
|---|---|
| rclone 驱动 | `onedrive` |
| `token` | `rclone config show` 输出的 `token` |
| `drive_id` | 同上 |
| `drive_type` | 同上（`personal`、`business` 或 `documentLibrary`）|
| `region` | 非国际版账号才需要：`us`、`de` 或 `cn` |
| `client_id`、`client_secret` | 只在 rclone 里用了自建应用时需要 |
| `path` | 存放图片的目录，如 `imgyoung` |

自定义模式里令牌原样保存，需要重新授权时替换 `token` 的值。保存后删除本机的临时 remote，避免两处同时刷新同一个令牌：

```bash title="终端"
rclone config delete onedrive-tmp
```

## 国内网盘：经自部署的聚合服务以 WebDAV 接入

rclone 没有阿里云盘、百度网盘、115、夸克等国内网盘的后端。能对接它们的开源聚合服务（如 Alist 一类）采用 AGPL-3.0 许可证，ImgYoung 不包含这些代码。

接入方法是自行部署这类聚合服务，让它对外提供 WebDAV，再用 ImgYoung 的通用 WebDAV 模板接入。两者是独立的进程，只通过网络协议交互，ImgYoung 的许可证不受 AGPL 影响；这些网盘的接口与风控变化由聚合服务跟进。

<Steps>
<Step>
按聚合服务自己的文档部署它，挂载要用的网盘，并开启 WebDAV。
</Step>
<Step>
为 ImgYoung 建一个专用账号，给它读、写、删除权限。深探测、每日对账与渠道清理都要删除对象，没有删除权限的渠道无法通过深探测。
</Step>
<Step>
在 ImgYoung 新建 WebDAV 渠道：「服务地址」填聚合服务的 WebDAV 地址（Alist 为 `https://域名/dav/`），「服务类型」选「其他（坚果云 / Alist / 群晖等）」，填好账号密码；「存储目录」填该网盘在聚合服务里的挂载路径下的一个专用目录。
</Step>
<Step>
点「测试连接」确认写、读、删都通过，再设一个低于对象存储渠道的优先级，保存。
</Step>
</Steps>

## 网盘渠道的固有限制

- **始终走代理**：网盘普遍不提供稳定的公开直链，所以网盘模板没有「公开访问地址」，表单也不显示「允许 302 直链」与「自动创建存储桶」。即使访问模式是 `redirect`，网盘上的图片也经 ImgYoung 代理输出。
- **频率与流量限制**：网盘对请求频率与流量的限制远比对象存储严格，图片访问量大时容易被限流或触发风控。周期轻探测每轮会对每个渠道发一次只读请求。
- **全量镜像**：与其他渠道一样，网盘渠道最终要存下全站的全部图片。

因此网盘更适合作为**低优先级的备份渠道**：把它的优先级设得低于对象存储渠道，平时只接收异步补齐；优先级更高的渠道都不可用（或这张图在它们上面还没有就绪副本）时，访问才会切到它。这完全通过优先级来设置，见[渠道与容灾](./index.mdx#主渠道与备份渠道)。

## 错误码

| 错误码 | 何时出现 | 含义 |
|---|---|---|
| `oauth_no_refresh_token` | 保存（400）| 粘贴的令牌会过期，却没有带刷新令牌 |
| `oauth_token_invalid` | 保存（400）| 粘贴的内容无法解析为令牌 |
| `oauth_base_url_required` | 发起一键授权（400）| 还没有填写对外站点地址；先填写，或改用粘贴令牌 |
| `oauth_exchange_failed` | 一键授权的结果 | 换取令牌失败，核对应用凭证与回调地址 |
| `oauth_denied` | 一键授权的结果 | 在服务商页面拒绝或取消了授权；参数 `detail` 为服务商返回的原因 |
| `channel_deleting` | 发起一键授权（409）| 渠道在清理中，不能重新授权 |
| `channel_config_changed` | 保存（409）| 保存期间渠道配置被另一次编辑或令牌刷新改动，重新保存即可 |
