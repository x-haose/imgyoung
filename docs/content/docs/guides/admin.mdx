## 登录

管理后台就在站点根路径，例如 `https://img.example.com/`。

首次启动后，用内置管理员登录：登录名 `admin`，出厂密码 `imgyoung123`。登录后会直接进入「设置管理员密码」页。

<Callout type="warn" title="先修改出厂密码">
出厂密码是公开的，实例暴露到公网之前务必先改掉。改密之前，这个账号只能修改密码、退出登录和查看当前账号；其他后台操作（包括后台上传、签发 Token、管理渠道）一律返回 403，不论请求来自后台页面还是脚本。
</Callout>

初始密码不能通过环境变量设置，也不能通过环境变量预置 Token。没有图形界面的部署，同样先登录后台改密，再签发上传 Token。

忘记密码见[重置密码](../operations/password-reset.mdx)。

## 页面导览

左侧栏分三组，普通用户只能看到其中一部分：

| 分组 | 页面 | 谁能看到 |
|---|---|---|
| 内容 | 总览、图片、上传 Token | 全部用户 |
| 站点 | 存储渠道、用户、疑似重复、待清理、审计日志 | 管理员 |
| 其他 | 使用指南 | 全部用户 |
| 其他 | 设置 | 管理员 |

顶栏有页面搜索（⌘K / Ctrl+K 打开命令面板）、语言切换和主题切换。侧栏底部的账号菜单里有「修改密码」和「退出登录」。

### 总览

管理员看到全站概况：

- **指标卡**：图片、存储用量（原图字节合计，副本不重复计算）、用户、访问次数（附估算流量）、待清理、疑似重复。
- 「存储渠道」：每个渠道的健康状态和已存字节。
- 「告警」：当前未恢复的告警，条件不再成立时自动恢复。点「历史记录」打开设置里的「告警历史」标签。
- 「热门图片」：访问次数最多的 10 张图片。

告警有五种，描述按界面语言显示：

| 告警 | 描述内容 |
|---|---|
| 渠道不健康 | 失败原因，写法同渠道列表 |
| 副本补齐失败 | 失败的副本数 |
| 渠道用量超阈值 | 用量与阈值 |
| 渠道排空失败 | 失败原因，写法同渠道列表 |
| 备份失败 | 备份的报错 |

页面不认识的告警类型显示服务端记下的中文描述。

<Callout type="warn" title="数据只存在这台主机上">
找不到一个健康、不在清理中、且驱动不是 local 的渠道时，总览顶部会显示这条提示，一个健康渠道都没有时同样显示。这时图片副本和元数据库快照都只在这台主机上，主机损坏就会全部丢失。添加一个对象存储或网盘渠道即可解除；已经有了，到「存储渠道」页查看它为什么不健康。
</Callout>

普通用户看到自己的图片数、已用空间和配额。

「快速开始」卡片在还没有图片时出现：

- 管理员：全站还没有图片时显示三步，即确认存储渠道、签发上传 Token、开始上传。
- 普通用户：自己还没有上传过图片时显示「你还没有上传过图片，两步开始使用」，即签发上传 Token、开始上传。

访问次数与估算流量的计算方式见[访问图片](./access.mdx)。

### 图片

图片网格。管理员看到全站的图片（「全站图片」），普通用户只看到自己的（「我的图片」）。

- **搜索**：按短 ID 或文件名搜索。
- 「筛选」：「上传来源 Token」「上传时间」「仅看已豁免」；管理员另有「归属用户」。
- 「选择」：多选后「批量删除」，一次最多 100 张。部分删除失败时，提示删除与失败的张数，并给出第一张失败的原因（如图片已在别处被删除）。
- 「上传图片」：直接在后台上传，见[上传](./upload.mdx#在管理后台上传)。

点开一张图片，会打开详情抽屉：

- 「分享链接」：完整链接，可「复制为」URL、Markdown、HTML 或 BBCode。下方列出可用的缩放宽度，点击即复制带 `?w=` 的链接。设置了对外站点地址时，链接使用它的域名。
- **元数据**：格式、尺寸、大小、归属、来源 Token、引用数、上传时间、最近访问、访问次数、到期（可「修改有效期」）、清理豁免、SHA-256。
- 「副本分布」：这张图在每个渠道上的副本状态（待补齐 / 上传中 / 就绪 / 失败）和尝试次数。补齐失败过的副本显示「最近错误」，写法同渠道的失败原因，见下文[失败原因](#失败原因)。
- 「删除」；管理员另有「审计记录」，打开以这张图为目标的审计日志。

有效期与清理豁免见[生命周期与查重](./lifecycle.mdx)。

### 存储渠道

在这里新建、编辑、探测和删除渠道，设置优先级、加密和 302 直链。「副本」列显示每个渠道上就绪、待补齐和失败的副本数。表单字段和各类后端的配置见[存储渠道](../channels/index.mdx)，下面只列在后台操作时需要知道的几点。

#### 配置与授权

- **网盘授权**：网盘模板在授权控件上方有「应用 Client ID」「应用 Client Secret」两个字段，随渠道配置加密保存。用「一键授权」必须先填 Client ID。用「粘贴令牌」时，如果令牌是用自建应用授权的，也要填这两项，因为令牌只能由签发它的应用续期。
- **凭证显示为掩码**：编辑渠道时，凭证类参数显示为掩码，不修改就保留原值。除密码、密钥和令牌外，访问密钥 ID、WebDAV 用户名、Client ID 等也算凭证，由服务端按各后端声明的参数属性判断。自定义模式下无法判断哪个键是凭证，所有参数值都用掩码输入框显示，可以逐个点开查看。
- **保存冲突**：两个人同时编辑同一个渠道，或者保存期间服务商刷新了令牌并写回渠道，后保存的一次不会生效，返回 409，提示配置在保存期间已被改动。再保存一次即可。
- **令牌刷新**：「测试连接」期间服务商刷新了授权令牌时，测试结果下方会提示表单已换用新令牌、原令牌可能已失效，授权字段显示「已授权」，接着保存即可。保存失败时令牌同样不会丢：服务商在保存过程中刷新了表单提交的令牌，提示里会说明表单已换用新令牌，改正后再次保存即可，不需要重新授权。编辑时沿用的已存令牌如果被刷新，会直接写回该渠道。
- **加密与直链**：设置里开启「新渠道默认加密」后，新建渠道的「服务端加密」保持「继承全局默认」就会加密，这时「允许 302 直链」不可用。需要直链时，把「服务端加密」设为「强制关闭」。

#### 失败原因

「异常」与「清理中」徽标的提示里显示最近一次失败的原因，格式为「归类说明（原文）」：

- 归类说明随界面语言显示，如「认证失败（401）：检查用户名、密码或授权令牌是否有效」。
- 原文是错误链最内层的原因，多为服务商或网络库返回的英文，已去除凭证，最长 200 个字符。
- 无法归类时只显示原文。

「重新探测」「测试连接」失败时显示同样的内容。

渠道装载失败时（配置无法解密、驱动构造失败、构造超过 30 秒等），列表里显示为「异常」，原因前加「装载失败：」。主密钥与写入配置时用的不一致时，归类为「渠道配置无法解密」。

各渠道并行装载，一个不可达的后端不会拖住启动和健康检查。健康检查每轮都会重试装载，「重新探测」也会先重试装载。渠道装载成功并通过探测后，才恢复健康、重新参与读写。

#### 导出 rclone 配置

渠道行菜单里的「导出 rclone 配置」下载该渠道的 rclone 配置文件 `imgyoung-channel-<渠道 ID>.rclone.conf`，清理中的渠道没有这一项。用标准 rclone 加载这个文件，就能脱离 ImgYoung 读写这个渠道上的数据；加密渠道还多一个加密层远端，经它读出的就是明文。

- 文件开头的说明注释随界面语言为中文或英文。
- 每次下载都记入审计日志。
- 对话框在下载成功后才关闭；失败时保持打开，可以重试。下载途中关闭对话框会中止下载。

文件内容与用法见[渠道存储加密](../channels/encryption.mdx)与[存储渠道](../channels/index.mdx)。

<Callout type="warn" title="配置文件里含凭证">
文件里含渠道凭证和授权令牌，加密渠道还含解密密码。要和主密钥一样离线妥善保存。
</Callout>

#### 删除渠道

删除渠道时，对话框里的「同时删除本服务写在该渠道上的数据」默认勾选：

| 选择 | 渠道 | 渠道上的数据 |
|---|---|---|
| 保持勾选，点「删除并清理」 | 显示为「清理中」，数据删完后自动移除 | 图片副本、元数据库快照和深探测的残留文件在后台逐个删除 |
| 取消勾选，点「仅移除」 | 立即移除 | 图片副本和元数据库快照原样保留，需要时自行到存储商处理 |

如果本渠道持有某些图片唯一的就绪副本，两种删除都会被拒绝，返回 409，提示里给出这类图片的张数；清理中的渠道上的副本不算数。这时先添加或修复其他渠道，等这些图片在其他渠道上的副本全部就绪（「副本」列里没有「待补」与「失败」），或者删除这些图片，再删除渠道。

「删除并清理」只删除以下对象：有记录的图片副本、系统目录 `_imgyoung/` 下的对象（含元数据库快照）和深探测残留。渠道里的其他对象不动：别的程序写的文件不受影响，上传失败留下、还没被对账删除的无主对象也会留在存储商处。

渠道进入「清理中」后，编辑、测试连接、重新探测和重新授权都会被拒绝（409），只能「直接移除」。「直接移除」立即移除渠道并停止清理：除了正在删除的那一个对象，其余远端对象（含快照）原样保留。

#### 清理失败时

清理失败后会按退避间隔自动重试，不会停止。如果渠道只是暂时不可用，恢复后会自己清完。

- 同一个清理任务第 4 次尝试仍失败时（按内置的退避间隔，约在第一次失败 98 秒后），失败原因才写进渠道，显示在「清理中」徽标的提示里，前面加清理失败的说明，同时开启「渠道排空失败」告警。在此之前渠道只显示「清理中」，一次网络抖动不会触发告警。单次清理任务被停机打断，或超时前已删掉部分对象，都不算失败，也不计入尝试次数；一个对象也没删掉就超时，按失败计。
- 渠道无法装载时清理无从进行，装载失败的原因会立即显示，并开启「渠道排空失败」告警。渠道装载成功后，这个原因随即清除、告警恢复，之后只有清理本身的失败才会再开启告警。
- 清理失败的原因和告警会保留到清理完成或渠道被移除。

凭证已失效或存储桶已不存在，重试也无法成功时，对该渠道点「直接移除」。已经知道清理不了的渠道，删除时直接选「仅移除」。

### 审计日志

管理操作的记录，只追加、不修改。可以按「动作」「操作者」（用户 ID）、「目标」（图片短 ID、渠道 ID、Token ID 等，精确匹配）和「时间范围」筛选。

渠道的新建、编辑、导出和删除都以渠道 ID 为目标，新建和编辑的详情里还带有 `name=` 渠道名，所以按渠道 ID 能查到一个渠道的全部操作。渠道 ID 不复用，已删除渠道的 ID 不会分给新渠道。

记录的动作：

| 对象 | 动作 |
|---|---|
| 渠道 | 新建渠道、编辑渠道、删除渠道、导出渠道 rclone 配置 |
| Token | 签发 Token、吊销 Token、轮换 Token、删除 Token |
| 用户 | 新建用户、更新用户（含改密与重置密码）、删除用户 |
| 图片 | 修改图片（有效期、清理豁免）、删除图片（含 S3 DeleteObject）|
| 裁决 | 合并重复图、忽略重复图 |
| 设置 | 修改配置、添加防盗链白名单、移除防盗链白名单 |
| 数据 | 导出数据、立即备份、恢复备份 |

上传本身和到期自动删除不记审计。保留期由「审计日志保留天数」（`audit_retention_days`）决定，默认 0，表示永久保留。

### 使用指南

后台内置的速查页，所有用户可见。curl、PicGo 和 S3 客户端的配置示例里已经填好了当前站点的地址。

### 设置

仅管理员可见，分四个标签：

- 「运行配置」：全部运营配置，按访问与链接、上传限制、生命周期、按需处理、查重、可靠性与渠道、CDN 缓存清理、告警与审计分组。改完点「保存修改」立即生效，不需要重启。有取值不合法时整批都不保存，提示里指出是哪个配置键、违反了哪条规则。见[配置](../configuration.mdx)。
- 「防盗链」：Referer 白名单和「空 Referer 放行」开关，见[访问图片](./access.mdx#hotlink-protection)。
- 「备份与导出」：元数据库快照按「备份间隔」自动写到每个健康渠道，各渠道各自保留最近几份。快照表列出快照、大小、时刻和「所在渠道」（存放它的渠道，按优先级排列），可以「立即备份」「下载」「恢复」；另有「导出 JSON」导出全部元数据。用法、经反向代理操作时的注意事项和错误码见[备份与恢复](../operations/backup.mdx)。
- 「告警历史」：全部告警的开启与恢复记录。告警 Webhook 见[监控](../operations/monitoring.mdx)。

「运行配置」下方的「引导配置」卡片只读显示以下内容，环境变量修改后需要重启进程才会生效：

| 类别 | 内容 |
|---|---|
| 环境变量 | 监听地址、数据目录、信任的反代网段、`/metrics` 放行网段 |
| 构建信息 | 服务端版本、构建提交、构建时刻 |
| 内置策略 | 登录限速参数、副本对账间隔 |

- 数据目录显示启动时解析出的绝对路径，相对路径按启动时的工作目录解析。
- 网段类变量未设置时，显示默认网段。
- 网段类变量显式设为空字符串时，「信任的反代网段」显示「空：不采信任何转发头」，「/metrics 放行网段」显示「空：不对任何地址开放」。

后台的下载（导出 JSON、下载快照、导出 rclone 配置）都先完整取回文件，成功后才交给浏览器保存。失败或传输中断时，页面右下角的提示里给出原因，不会把错误响应或残缺的内容存成文件。

## 角色与权限

账号只能由管理员在「用户」页创建，不开放注册。角色有两种：

| 能力 | 管理员 | 普通用户 |
|---|---|---|
| 上传（Token、后台、S3）| 可以 | 可以 |
| 查看、删除图片 | 全站 | 只限自己的 |
| 修改图片有效期 | 全站 | 只限自己的 |
| 设置清理豁免 | 可以 | 不可以 |
| 签发、轮转自己的 Token，查看自己 Token 的 S3 配置 | 可以 | 可以 |
| 查看、吊销、删除别人的 Token | 可以 | 不可以 |
| 存储渠道、用户、疑似重复、待清理、审计日志、设置 | 可以 | 不可以 |

普通用户之间看不到彼此的图片和 Token，打开别人的图片详情会得到 404。图片链接本身是公开的，知道链接的人都能访问。

可以有多个管理员。内置管理员（用户 ID 为 `default`）受保护：不能被禁用、降级或删除，但可以改名。任何管理员都不能删除自己。

在「用户」页：

- 「建号」：填写登录名、初始密码（至少 8 个字符，建好即可登录）、角色、配额和默认有效期。
- 「编辑」：修改登录名、角色、配额、默认有效期，或勾选「禁用」。禁用会立即结束该用户的全部会话，其 Token 也无法再上传。
- 「重置密码」：设置新密码，该用户的全部会话立即失效。
- 「删除」：名下还有图片时会被拒绝，需要先删除图片。删除时该用户的 Token 和会话一并删除，审计记录保留。

## 配额与上传频控

- **配额**：建号或编辑时为每个用户设置，单位 MB 或 GB，留空或填 0 表示不限。上传后会超出配额时返回 403。用户在总览查看自己的已用空间与配额，管理员在「用户」页的「用量 / 配额」列查看。
  配额按引用计全额：每张图都按其物理文件的完整大小计入，后台查重合并不会减少已用量，所以上传与别人相同的图片也不会少计用量。
- **上传频率上限**：「设置 → 运行配置」里的 `upload_rate_per_min`，对每个用户统一生效，默认 0，表示不启用。同一用户经 Token、后台和 S3 兼容接口的上传共用一份额度。
- **上传并发上限**：`max_concurrent_uploads`，全站共用，默认 8。

超限时的行为和状态码见[上传](./upload.mdx#格式与上限)。

## 上传 Token [#upload-tokens]

上传 Token 放在 `Authorization: Bearer` 头里使用时，只能调用 `/api/upload` 和 `/api/upload/url`。每枚 Token 还对应一组 S3 凭证（见下文的「S3 客户端配置」），可以经 S3 兼容接口上传，也能读取和删除该用户经 S3 上传的对象。两者都不能登录后台，也不能调用后台接口。后台使用密码登录后的会话，见[会话与安全](#会话与安全)。

Token 或其 S3 凭证泄露时，影响限于以这个用户的身份上传，以及该用户经 S3 上传的对象。建议每个客户端签发一枚，泄露时单独吊销那一枚即可。

### 签发

在「上传 Token」页点「签发 Token」，填写：

- 「用途名称」：如 `picgo`、`blog-script`，最多 64 个字符。同一用户的有效 Token 不能重名；同名的旧 Token 已过期时，签发新 Token 会自动吊销那条过期记录。
- 「有效期」：永久、7 天、30 天、90 天或 365 天。到期后与吊销一样失效。

签发后，对话框显示 Token 明文（`imgy_` 加 43 个字符）。**明文只显示这一次**，关闭后无法再查看。数据库只保存它的 SHA-256 和前 12 个字符的识别前缀。

使用时放在请求头里：`Authorization: Bearer <token>`。

### 列表与状态

列表显示名称、识别前缀、状态（有效 / 已过期 / 已吊销）、到期、最近使用和签发时间。「最近使用」大约每分钟批量更新一次。

每张图片都记录了经由哪个 Token 上传，「图片」页可以按「上传来源 Token」筛选。

### 行操作

点行末的「更多操作」：

| 操作 | 适用于 | 作用 |
|---|---|---|
| 「S3 客户端配置」 | 自己的有效 Token | 查看这枚 Token 对应的 S3 access key、secret 和端点，可以反复查看。见[上传客户端](./clients.mdx) |
| 「轮转」 | 自己的有效 Token | 签发一枚同名的新 Token 并吊销旧的，两者在同一次操作中完成。新明文同样只显示一次，旧 Token 和它的 S3 凭证立即失效。原来永久的仍为永久；原来有有效期的，从现在起按同样的时长重新计算 |
| 「吊销」 | 有效 Token | 立即失效，使用它的客户端无法再上传，S3 凭证同时失效。记录保留 |
| 「删除记录」 | 已吊销或已过期的 Token | 从列表中移除，审计记录保留。有效的 Token 不能删除，需要先吊销 |

### 管理员查看别人的 Token

管理员可以用「按用户查看」切换到任意用户的 Token 列表，对其中的 Token「吊销」或「删除记录」。

「轮转」和「S3 客户端配置」只对本人开放。这两项会给出可用的凭证，对别人的 Token 执行就等于接管了对方的上传权限，以及对方经 S3 上传的对象。

## 会话与安全

| 机制 | 做法 |
|---|---|
| 密码存储 | argon2id（64 MiB 内存、3 轮、单线程），每个密码使用独立的随机盐。密码至少 8 个字符，按字符计，一个汉字算一个 |
| 登录限速 | 按客户端 IP 和登录名分别计数：各允许连续 5 次尝试，之后每 12 秒恢复 1 次，超出返回 429。登录成功后清零。经信任的反向代理时，客户端 IP 取自 `X-Forwarded-For` |
| 防用户名枚举 | 用户名不存在与密码错误返回同样的错误，校验耗时相近 |
| 会话 | 登录后下发 256 位随机会话 ID，放在 cookie `imgyoung_session` 里，带 `HttpOnly` 和 `SameSite=Lax`；客户端经 HTTPS 访问站点时另加 `Secure`。服务端只保存会话 ID 的哈希，数据库泄露也无法据此冒用会话。有效期固定 30 天，不随使用延长 |
| CSRF 校验 | 每个会话绑定一个 CSRF 令牌，所有改动状态的请求都必须在 `X-CSRF-Token` 头里带上它，后台页面会自动处理 |
| 出厂密码 | 内置管理员仍在使用出厂密码时，服务端只允许修改密码、退出登录和查看当前账号，其他后台接口返回 403 |
| 修改密码 | 「修改密码」需要输入旧密码；改完后该用户的所有设备都会下线，需要重新登录 |
| 禁用与重置密码 | 禁用用户或重置其密码，会立即结束该用户的全部会话；被禁用的用户无法登录，其 Token 全部失效 |
| 页面防护 | 所有响应都带 `X-Frame-Options: DENY` 和 `X-Content-Type-Options: nosniff`。后台页面另带内容安全策略（CSP）：脚本和接口请求只允许来自本站，页面不允许被其他页面嵌入 |

HTTPS 判定和客户端 IP 都依赖反向代理的转发头，只有来自 `IMGYOUNG_TRUSTED_PROXIES` 网段的转发头才会被采信。见[反向代理](../operations/reverse-proxy.mdx)。

## 界面语言与主题

- **语言**：顶栏的语言按钮在简体中文和 English 之间切换。首次访问时按浏览器语言选择，中文环境用简体中文，其余用英文；之后会记住你的选择一年。
- **主题**：顶栏的主题按钮可选浅色、深色、跟随系统，默认深色，选择同样会被记住。

这两项偏好都只保存在当前浏览器里，不随账号同步。

界面上的文字全部跟随所选语言，包括服务端返回的错误、渠道与副本的失败原因和告警描述：服务端只返回错误码、归类和参数，文案由界面按当前语言生成。只有服务商或网络库返回的原文保持原样，多为英文。

## 错误码

后台操作常见的错误码如下，完整列表见[接口参考](../api/index.mdx#错误格式)里的 `ErrorCode`。上传相关的错误码见[上传](./upload.mdx#状态码速查)，备份与恢复的见[备份与恢复](../operations/backup.mdx#错误码)。

| 操作 | 状态码 | 错误码 | 含义 |
|---|---|---|---|
| 除修改密码、退出登录、查看当前账号外的后台操作 | 403 | `must_change_password` | 内置管理员仍在使用出厂密码，先修改密码 |
| 保存渠道 | 409 | `channel_config_changed` | 保存期间配置被另一次编辑改动，或服务商刷新了授权令牌；再保存一次 |
| 删除渠道 | 409 | `channel_sole_replicas` | 本渠道持有部分图片唯一的就绪副本，提示里给出图片张数 |
| 编辑、测试连接、重新探测、重新授权 | 409 | `channel_deleting` | 渠道正在清理，只能「直接移除」 |
| 打开图片详情 | 404 | `image_not_found` | 图片不存在，或普通用户打开的是别人的图片 |
| 修改有效期 | 409 | `image_expired` | 图片已到期，不能再修改有效期 |
