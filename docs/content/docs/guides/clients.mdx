## 两种接入方式

| | 自定义 Web 图床 | S3 兼容接口 |
|---|---|---|
| 客户端要求 | 能发 multipart POST，并从 JSON 响应里取出链接 | 能向 S3 兼容存储上传（SigV4 签名、路径风格寻址）|
| 典型客户端 | PicGo + web-uploader 插件、PicList「高级自定义」、ShareX 自定义上传器 | PicList 内置 AWS S3、PicGo + s3 插件、aws CLI、rclone、各语言 S3 SDK |
| 凭证 | 上传 Token 明文 | 由上传 Token 派生的 access key 与 secret |
| 返回的链接 | 服务端返回 `/i/<短ID>` | 客户端按对象键自己拼 `/o/<用户 id>/<对象键>` |
| 有效期 | 可以逐次指定 | 只用默认值 |
| EXIF 处理 | 可以逐次指定档位，省略时用全局默认 | 不处理，按原字节保存 |
| 幂等键 | 支持 | 不支持 |
| 同名文件再传 | 每次都是一张新图 | 同一对象键按 S3 语义覆盖 |

两种方式最后都进同一条上传管道，格式、大小、配额、频控的规则相同，见[上传](./upload.mdx)。

凭证都在后台「上传 Token」页签发。建议每个客户端单独签发一个具名 Token，某个客户端泄露时只吊销它。

## 自定义 Web 图床

客户端要这样发请求：

- 以 multipart 表单 POST 到 `/api/upload`，文件字段名为 `file`；
- 带请求头 `Authorization: Bearer <Token>`；
- 从响应 JSON 的 `url` 字段取图片链接。

`url` 是绝对地址。经反向代理或 CDN 访问、对外域名与服务端收到的域名不同时，先在「设置 → 运行配置」填好「对外站点地址」，否则返回的链接会是反代内侧的地址。

### PicGo：web-uploader 插件

PicGo 本身没有通用的 HTTP 上传方式。在插件设置里搜索并安装 `web-uploader`（npm 包 `picgo-plugin-web-uploader`），图床列表里会多出「自定义Web图床」，按下表填写：

| 插件参数 | 配置键 | 填写 |
|---|---|---|
| API地址 | `url` | `https://img.example.com/api/upload` |
| POST参数名 | `paramName` | `file` |
| JSON路径 | `jsonPath` | `url` |
| 自定义请求头 | `customHeader` | `{"Authorization": "Bearer imgy_xxxxxxxx"}` |
| 自定义Body | `customBody` | 可选，作为额外的表单字段一起提交，如 `{"ttl": "never", "exif_policy": "strip"}` |

`customBody` 里的值要写成字符串。

### PicList：高级自定义

PicList 内置的「高级自定义」图床填写同样的内容：

- 接口地址：`https://img.example.com/api/upload`
- 请求方式：POST
- 文件字段名：`file`
- 请求头：`Authorization: Bearer imgy_xxxxxxxx`
- 返回值中链接的 JSON 路径：`url`

要指定有效期或 EXIF 档位，把 `ttl`、`exif_policy` 作为附加的表单字段。

### ShareX：自定义上传器

把下面的内容保存为 `imgyoung.sxcu`，在 ShareX 的自定义上传器设置里导入，再把图片上传目标选为它：

```json title="imgyoung.sxcu"
{
  "Version": "17.0.0",
  "Name": "ImgYoung",
  "DestinationType": "ImageUploader",
  "RequestMethod": "POST",
  "RequestURL": "https://img.example.com/api/upload",
  "Headers": {
    "Authorization": "Bearer imgy_xxxxxxxx"
  },
  "Body": "MultipartFormData",
  "FileFormName": "file",
  "URL": "{json:url}",
  "ErrorMessage": "{json:error}"
}
```

`URL` 从响应里取图片链接。`ErrorMessage` 取错误信封里的 `error`，上传失败时 ShareX 显示的就是中文原因，如 `文件超过大小上限(50 MB)`。

### 上传失败时

上传失败时，响应体是错误信封 `{code, error, params}`，例如 `{"code":"upload_quota_exceeded","error":"存储配额已满"}`。

- `error` 是填好参数的中文原因。能读取响应正文的客户端可以直接展示它，比如上文 ShareX 配置里的 `ErrorMessage`。
- 自己写的脚本请按 `code` 判断失败种类，不要匹配文字。

错误码与信封的详细说明见[上传](./upload.mdx#错误响应)。

## S3 兼容接口

ImgYoung 在 `/s3` 下实现了 S3 协议的一个子集，支持上传、查看元数据、下载与删除单个对象。凭证由上传 Token 派生：吊销 Token，对应的 S3 凭证同时失效。

列举对象、分片上传等操作不受支持，依赖它们的客户端命令（如 `aws s3 sync`、`rclone sync`）无法使用，见[支持的操作](#支持的操作)。

### 取得 S3 配置

在后台「上传 Token」页，点某个有效 Token 行末的「更多操作」→「S3 客户端配置」。弹窗给出全部参数，逐项复制即可：

| 弹窗字段 | 示例值 | 说明 |
|---|---|---|
| 应用密钥 ID | `imgy_AbCdEfG` | 即 Token 的识别前缀（12 个字符）|
| 应用密钥 | 64 位十六进制 | 由主密钥按该 Token 派生，不存入数据库，可以随时回来重看 |
| 桶名 | `images` | 没有桶的概念，填任何桶名都接受，桶名也不进对象键 |
| 区域 | `us-east-1` | 不区分区域，填任何值都接受 |
| 自定义节点 | `https://img.example.com/s3` | 结尾的 `/s3` 是接口前缀，不能省 |
| 自定义域名 | `https://img.example.com/o/<用户 id>` | 拼图片链接用，含你的用户 id |

- 节点与域名按「对外站点地址」生成；没有设置时，按打开后台所用的地址推导。
- **必须用路径风格寻址**（path-style，请求形如 `/s3/<桶>/<对象键>`）。自部署的服务没有桶子域名，客户端有「路径风格」「ForcePathStyle」之类的开关时请打开。
- 只能查看自己的 Token 的 S3 配置，管理员也看不到别人的。
- 轮转 Token 后，access key 与 secret 都会变，客户端要换成新值。更换主密钥会让全部 S3 secret 失效。
- Token 吊销、过期或所属用户被禁用后，签名校验一律失败。

下面各客户端的示例里，把 `imgy_AbCdEfG`、`<secret>`、`<用户 id>` 换成弹窗里的实际值。

### PicList：内置 AWS S3

PicList 自带「AWS S3」图床，按配置键对应填写（界面上的字段名随版本可能不同）：

| 配置键 | 填写 |
|---|---|
| `accessKeyID` | 弹窗里的「应用密钥 ID」 |
| `secretAccessKey` | 弹窗里的「应用密钥」 |
| `bucketName` | `images` |
| `uploadPath` | 对象键模板，例如 `{year}/{month}/{md5}.{extName}` |
| `region` | `us-east-1` |
| `endpoint` | `https://img.example.com/s3` |
| `pathStyleAccess` | 开启 |
| `urlPrefix` | `https://img.example.com/o/<用户 id>` |
| `disableBucketPrefixToURL` | 开启。否则在路径风格下，PicList 会在链接里插入桶名，得到打不开的地址 |

### PicGo：s3 插件

PicGo 没有内置 S3 上传。在插件设置里安装 `s3`（npm 包 `picgo-plugin-s3`），图床列表里会多出「Amazon S3」。这个插件推荐用「自定义输出 URL 模板」（`outputURLPattern`）生成链接，其中 `{path}` 是上传后的完整对象键：

| 配置键 | 填写 |
|---|---|
| `accessKeyID` / `secretAccessKey` | 弹窗里的「应用密钥 ID」与「应用密钥」 |
| `bucketName` | `images` |
| `uploadPath` | 例如 `{year}/{month}/{md5}.{extName}` |
| `region` | `us-east-1` |
| `endpoint` | `https://img.example.com/s3` |
| `pathStyleAccess` | 开启（界面上叫 ForcePathStyle）|
| `outputURLPattern` | `https://img.example.com/o/<用户 id>/{path}` |

用 `{md5}` 之类的内容哈希做对象键：同一张图重复上传得到同一个键，不同的图不会互相覆盖。

### aws CLI

```ini title="~/.aws/credentials"
[imgyoung]
aws_access_key_id = imgy_AbCdEfG
aws_secret_access_key = <secret>
```

```ini title="~/.aws/config"
[profile imgyoung]
region = us-east-1
s3 =
  addressing_style = path
  multipart_threshold = 64MB
```

```bash title="终端"
# 上传
aws --profile imgyoung --endpoint-url https://img.example.com/s3 \
  s3 cp ./photo.png s3://images/blog/2026/photo.png

# 取回元数据与删除
aws --profile imgyoung --endpoint-url https://img.example.com/s3 \
  s3api head-object --bucket images --key blog/2026/photo.png
aws --profile imgyoung --endpoint-url https://img.example.com/s3 \
  s3 rm s3://images/blog/2026/photo.png
```

上传后的链接是 `https://img.example.com/o/<用户 id>/blog/2026/photo.png`。

- `aws s3 cp` 对超过 `multipart_threshold`（默认 8 MB）的文件改用分片上传，而分片上传不受支持。把它调到大于「单图上限」的值，或改用 `aws s3api put-object` 单次上传。
- `aws s3 ls`、`aws s3 sync` 依赖列举对象，不可用。

### rclone

```bash title="终端"
rclone config create imgyoung s3 \
  provider=Other \
  access_key_id=imgy_AbCdEfG \
  secret_access_key=<secret> \
  endpoint=https://img.example.com/s3 \
  region=us-east-1 \
  force_path_style=true \
  no_check_bucket=true

rclone copyto ./photo.png imgyoung:images/blog/2026/photo.png
```

- `no_check_bucket=true` 让 rclone 跳过上传前的建桶检查，服务端不支持建桶。
- 只用 `copyto`、`deletefile` 这类按单个对象操作的命令。`ls`、`sync`、按目录 `copy` 依赖列举对象，不可用。

### 其他 S3 SDK

任何语言的 S3 SDK 都按同样的要点配置：

- 端点设为 `https://img.example.com/s3`；
- 开启路径风格寻址；
- 区域随意填，如 `us-east-1`；
- 只用 PutObject、HeadObject、GetObject、DeleteObject；
- 不要让 SDK 自动切换到分片上传。

### 对象键别名 [#object-key-aliases]

经 S3 上传的图片，除了短链 `/i/<短ID>`，还可以按对象键访问：

```text
https://img.example.com/o/<用户 id>/<对象键>
```

- 用户 id 是不可变的账号标识，不是登录名。内置管理员为 `default`，其他用户是建号时生成的 10 位随机串，可以在「用户」页的 ID 列或 S3 配置弹窗的「自定义域名」里看到。
- 对象键只在同一用户内唯一，所以链接里要带用户 id。用 id 而不用登录名，是因为登录名可以修改：改名后旧名可能被别人占用，之前分享的链接就会指向别人的图。
- `/o/` 与 `/i/` 是同一张图的两个入口，按需处理、格式协商、防盗链、访问计数完全一致，只有缓存方式不同，见下文。
- 短 ID 在 PutObject 响应头 `x-amz-meta-image-id` 里，也能在后台「图片」页查到。

### 同键覆盖

对同一对象键再次 PutObject，按 S3 语义覆盖：

- 这个对象键指向新上传的图，`/o/` 链接随之显示新图。
- 旧图不会被删除。它的短 ID 可能已经分享出去，短链继续可用，也继续占用存储与配额。不需要时，到后台「图片」页手动删除。
- DeleteObject 只删除对象键当前指向的那张图。

因为对象键可以被覆盖，`/o/` 链接与 S3 GetObject 的响应是 `Cache-Control: public, no-cache` 加强 `ETag`。浏览器与 CDN 可以缓存，但每次使用前都要带 `ETag` 向本服务确认，内容没变时得到 304；覆盖后，下一次确认就拿到新图。短链 `/i/<短ID>` 始终指向同一张图，按一年不可变缓存。见[访问图片](./access.mdx#caching)。

## S3 兼容接口参考

### 支持的操作

| 操作 | 请求 | 行为 |
|---|---|---|
| PutObject | `PUT /s3/<桶>/<对象键>` | 走上传管道。响应头 `ETag` 为上传正文的 SHA-256，`x-amz-meta-image-id` 为这张图的短 ID |
| HeadBucket | `HEAD /s3/<桶>` | 凭证有效即返回 200 |
| HeadObject | `HEAD /s3/<桶>/<对象键>` | 返回对象的元数据头。会按优先级确认某个渠道上读得到这个对象的元数据（只查元数据，不读内容），都读不到时与 GetObject 一样返回 503 |
| GetObject | `GET /s3/<桶>/<对象键>` | 返回保存的原图，不做按需处理，不计访问，不受防盗链约束；缓存头与 `/o/` 别名相同 |
| DeleteObject | `DELETE /s3/<桶>/<对象键>` | 删除该对象键当前指向的图；对象不存在也返回 204 |

其余操作一律返回 501，S3 错误码 `NotImplemented`（文案 `不支持的 S3 操作`），包括：

- 列举桶与对象（`ListBuckets`、`ListObjects`）；
- 建桶；
- 分片上传；
- 批量删除；
- 复制对象（`CopyObject`，即带 `x-amz-copy-source` 头的请求）；
- 带子资源查询参数的请求，如 `?acl`、`?tagging`、`?uploads`、`?partNumber=…&uploadId=…`。除 `x-id` 外的任何查询参数都视为子资源。

S3 客户端不会自动重试 501，会直接报错。这项检查在验签之后，签名不对的请求先得到签名错误。

另外两种不支持的用法在验签阶段就被拒绝，返回 400：

- 预签名 URL（签名放在查询串里）：没有 `Authorization` 头，返回 `AuthorizationHeaderMalformed`；
- SigV2 签名：返回 `InvalidRequest`。

客户端随请求带的 ACL 头不报错，也不起作用。

### 签名与请求正文

- 只认 `Authorization` 头里的 `AWS4-HMAC-SHA256` 签名。
- 请求时间与服务器时间相差超过 15 分钟即拒绝。
- 支持 `UNSIGNED-PAYLOAD`，也支持 aws CLI v2 等默认使用的 `aws-chunked` 分块正文。
- 请求声明了正文哈希时，服务端会核对它与实际正文一致。

### 上传时的取值

- 对象键是桶名之后的整段路径（URL 解码后），最长 1024 字节，不能含控制字符，不能以 `/` 开头。对象键在同一用户内唯一。
- 文件名取对象键的最后一段。
- 有效期取用户默认值；用户没有设置时，取全局默认值。
- 不做 EXIF 处理，全局 EXIF 默认档对 S3 上传不生效。保存的字节与上传的完全一致，PUT 响应的 ETag 与之后 GetObject 的 ETag 相同。

### 错误码

错误以 S3 风格的 XML 返回，客户端按 `Code` 区分。S3 兼容接口的错误一律是这种 XML，不返回 JSON 错误信封。

| 情形 | 状态码 | Code |
|---|---|---|
| 签名不符、access key 不存在、Token 已失效 | 403 | `SignatureDoesNotMatch` |
| 请求时间偏差超过 15 分钟 | 403 | `RequestTimeTooSkewed` |
| 缺少或无法解析 `Authorization` 头 | 400 | `AuthorizationHeaderMalformed` |
| 不是 `AWS4-HMAC-SHA256` 签名 | 400 | `InvalidRequest` |
| 超过单图大小上限 | 400 | `EntityTooLarge` |
| 不是支持的图片，或超过像素预算 | 400 | `InvalidRequest` |
| 存储配额已满 | 403 | `QuotaExceeded` |
| 对象键过长 / 含非法字符 / 缺失 | 400 | `KeyTooLongError` / `InvalidArgument` / `InvalidRequest` |
| 对象不存在，或指向的图已到期 | 404 | `NoSuchKey` |
| 上传时没有健康渠道可写，或同步写入的份数达不到最少同步副本数 | 503 | `ServiceUnavailable` |
| 对象暂时读不出来（GET / HEAD）| 503 | `ServiceUnavailable` |
| 上传并发已满，或该用户上传过于频繁 | 429 | `SlowDown` |
| 不支持的操作 | 501 | `NotImplemented` |
| 其余服务端错误 | 500 | `InternalError` |

429 带 `Retry-After` 头。上传并发已满时，文案为 `上传并发已满,请稍后重试`，`Retry-After` 为 1 秒；上传过于频繁时，文案为 `上传过于频繁,请稍后重试`，`Retry-After` 为 60 秒。S3 客户端把 `SlowDown` 当作可重试的错误，会退避后重试。
