## 链接形式

| 链接 | 适用 | 说明 |
|---|---|---|
| `/i/<短ID>` | 每张图 | 上传响应里的 `url`。短 ID 为 10 位，字符取自 `0-9A-Za-z` |
| `/o/<用户 id>/<对象键>` | 经 S3 兼容接口上传的图 | 按对象键访问的别名，对象键可含 `/`。见[上传客户端](./clients.mdx#object-key-aliases) |

两种链接都公开访问，不需要登录。它们的防盗链、访问计数、按需处理和渠道容灾读取完全一致，只有缓存方式不同，见[缓存与条件请求](#caching)。

图片删除后，链接立即返回 404；经 CDN 访问 `/i/` 链接时，CDN 已缓存的内容要靠缓存清理才会失效（`/o/` 链接每次都回源确认，随即返回 404），见[删除流程](./lifecycle.mdx#delete-flow)。设了有效期的图一到期就返回 404，不等清理扫描回收，见[生命周期与查重](./lifecycle.mdx)。

链接支持 GET 与 HEAD。HEAD 不带正文，也不计访问。其他状态码见页末[状态码](#status-codes)，完整接口定义见[接口参考：图片访问](../api/image-access.mdx)。

## 按需缩放与格式 [#on-demand-processing]

在链接后加查询参数，就能拿到缩放或转换格式后的版本：

```text
https://img.example.com/i/R0RjUyP1UW?w=400
https://img.example.com/i/R0RjUyP1UW?w=800&format=webp
https://img.example.com/i/R0RjUyP1UW?format=jpeg
```

| 参数 | 取值 | 说明 |
|---|---|---|
| `w` | 「宽度档」`process_widths` 中的值，出厂 `100,200,400,800,1600` | 按宽度等比缩小。目标宽度不小于原图宽度时不放大，只按目标格式重新编码 |
| `format` | 「目标格式」`process_formats` 中的值（出厂 `webp`、`jpeg`、`png`），或 `auto` | 指定输出格式。`auto` 与不写相同，按请求的 `Accept` 协商，见下文 |

参数只接受预设的档位，不在档位里的值返回 400。这样可以防止有人用任意取值占满 CPU 与磁盘缓存，同一组参数的结果也能反复命中缓存。

- 参数先校验，与原图格式无关：参数不合法时，任何原图都返回 400。
- `w` 只认规范写法，不带前导零与正负号。
- `w` 与 `format` 各至多出现一次。
- 其他查询参数不参与处理，也不会被拒绝，但会进入 CDN 默认的缓存键，缓存键的设置见 [CDN](../operations/cdn.mdx)。

档位在「设置 → 运行配置」的「按需处理」分组里修改，保存即生效。

### WebP 协商

不写 `format` 或写 `format=auto` 时，按请求的 `Accept` 头决定输出格式：

- `Accept` 含 `image/webp`，且 `webp` 在「目标格式」里：输出 WebP。
- 否则保持原格式。协商只会转成 WebP，不会把 WebP 原图转成别的格式给旧客户端。

现代浏览器的 `Accept` 都含 `image/webp`，所以浏览器直接打开 JPEG 或 PNG 的 `/i/` 链接，默认拿到的是 WebP。要拿原始字节，就显式写原图自己的格式，例如 JPEG 原图加 `?format=jpeg`。目标格式与原图相同且不缩放时，直接输出原图，不重新编码。

可缓存的协商响应都带 `Vary: Accept`，包括协商后直接输出的原图和 304 响应。显式指定了 `format` 的响应不带。GIF 不参与协商，也不带。

### 处理规则

| 情况 | 结果 |
|---|---|
| 不缩放，且格式与原图相同 | 直接输出原图 |
| GIF 原图 | 一律输出原图，保留动画。参数照样按档位校验：档外的值返回 400，档内的值被忽略 |
| JPEG 原图带 EXIF 方向标记 | 先按标记转正再缩放，宽度指的是转正后的宽度 |
| 原图超过像素预算，或大于当前的单图上限 | 不处理，降级输出原图（见下文）|

编码参数如下，输出都不带元数据：

| 输出格式 | 编码参数 |
|---|---|
| WebP | 质量 `process_quality_webp`（出厂 80），速度权衡 `process_webp_method`（出厂 4）|
| JPEG | 质量 `process_quality_jpeg`（出厂 85）|
| PNG | 无损，最高压缩 |

- 处理结果缓存在数据目录的 `variants/` 下，总量上限 `variants_cache_mb`（出厂 10240 MB），超出后按最近访问时间淘汰。修改编码参数后，之后的请求生成新的缓存项，旧的随淘汰清掉。
- 同一张图、同一组参数的并发首次请求只处理一次，结果共享。
- 同时处理的数量上限为 `process_workers`（出厂 4）。等待处理名额与读取原图共用一个超时 `process_timeout_ms`（出厂 5000 毫秒）。

处理失败时（等不到处理名额、解码失败等），降级输出原图。降级响应带 `Cache-Control: no-store`、不带 `ETag`，免得全尺寸原图被当成这个带参数链接的内容缓存下来。

## 缓存与条件请求 [#caching]

`/i/` 短链背后的原图不变（合并重复图是唯一例外，见下文），可以长期缓存。`/o/` 别名可能被同键覆盖、指向新图，所以缓存方每次使用前都要向本服务确认。

| 响应头 | 短链 `/i/` | 别名 `/o/` |
|---|---|---|
| `Cache-Control` | `public, max-age=31536000, immutable` | `public, no-cache` |
| `ETag` | 原图为 `"<SHA-256>"`，衍生图为 `"<SHA-256>-<宽度>-<格式>"`，不缩放时宽度为 `0` | 同左 |
| `Vary` | 输出格式由 `Accept` 协商决定时为 `Accept`，见 [WebP 协商](#webp-协商) | 同左 |
| `Last-Modified` | 原图为上传时刻，衍生图不带 | 同左 |
| `Content-Type` | 原图为上传时按内容判定的类型，衍生图为目标格式的类型 | 同左 |
| `X-Content-Type-Options` | `nosniff` | `nosniff` |

- 请求带 `If-None-Match` 且与当前 `ETag` 完全一致时，返回 304。304 同样带 `Cache-Control`、`ETag`，需要时带 `Vary`。
- 只按 `If-None-Match` 判断，不处理 `If-Modified-Since`。
- `public, no-cache` 允许浏览器与 CDN 存下响应，但每次使用前都要带 `ETag` 向本服务确认。内容没变时只回 304；同键覆盖后，下一次确认就拿到新图。

两种响应带 `Cache-Control: no-store`，不缓存：按需处理失败后的降级输出，以及 302 跳转。

短链指向的原图只在一种情况下会变：管理员合并疑似重复图后，被合并一方的链接输出保留方的图片。浏览器与 CDN 已缓存的旧内容，要等缓存过期才更新，见[生命周期与查重](./lifecycle.mdx#deduplication)。合并不会触发 CDN 缓存清除，需要立即生效时，手动清除 CDN 缓存，见 [CDN](../operations/cdn.mdx#cloudflare-缓存清除)。

## 访问模式：代理与 302

「设置 → 运行配置」里的「访问模式」`access_mode` 有两种取值：

- **proxy（出厂）**：ImgYoung 按优先级从持有就绪副本的健康渠道读取图片并转发给访客，读失败立即换下一个渠道。
- **redirect**：对能直链的渠道返回 302，访客直接从渠道的公开地址下载，不经本机转发。

| | proxy | redirect |
|---|---|---|
| 图片流量 | 经过本机 | 由渠道直接给访客 |
| 容灾 | 每次请求都可以换渠道读 | 302 指向的渠道出错时，访客直接看到错误；健康探测把该渠道判为异常后，本机才换目标 |
| 按需处理与 WebP 协商 | 可用 | 需要处理的请求仍走代理 |
| 防盗链 | 每次访问都校验 | 只校验 302 这一步，渠道的公开地址本身不受约束 |
| 加密渠道 | 可用 | 不能直链，回落代理 |
| 渠道的直链 | 不对外暴露 | 访客可见 |
| 访问计数 | 照常 | 照常，访客每次都先到本机 |

proxy 模式下，流量压力交给前置的 CDN 承担，见 [CDN](../operations/cdn.mdx)。redirect 适合没有 CDN、带宽有限的小型 VPS。

### redirect 模式下的跳转

ImgYoung 按优先级，在持有就绪副本的健康渠道中找第一个同时满足以下条件的渠道：

- 渠道设置里开了「允许 302 直链」；
- 不是加密渠道（密文不能直接给访客）；
- 配置了 `public_base_url`。

找不到这样的渠道时，照常走代理。直链与加密的设置见[存储渠道](../channels/index.mdx)。

302 的目标是 `<public_base_url>/<渠道内对象键>`。渠道内对象键形如 `<短 ID>_<SHA-256 前 8 位>`，不带扩展名。`public_base_url` 要指向渠道 `path` 对应的那一层目录。

对象键虽然不带扩展名，写入渠道时 ImgYoung 会把按内容判定的 `Content-Type` 一并交给存储后端。对象存储类渠道会保存它，浏览器直接打开 302 链接也能正常显示图片。

以下请求在 redirect 模式下仍由本机输出：

- 真正要生成衍生图的请求：JPEG、PNG、WebP 原图带 `w`，显式指定了与原图不同的 `format`，或协商到 WebP。
- 处理失败后的降级输出。
- 命中 `If-None-Match` 的请求：本机直接回 304，不跳转。

浏览器都声明支持 WebP，所以浏览器访问 JPEG、PNG 时默认走代理转码。想让浏览器访问也走 302，把 `webp` 从「目标格式」里去掉。最终输出原图的请求照常 302，例如 GIF 带合法参数，或 JPEG 带 `?format=jpeg`。

302 响应带 `Cache-Control: no-store`，浏览器与 CDN 都不缓存这次跳转：跳转目标随渠道健康、优先级与直链设置变化，图片删除或到期也要立即生效。跳转本身不带图片字节，每次回到本机只是几次数据库查询。

## 防盗链 [#hotlink-protection]

防盗链按请求的 `Referer` 头决定是否放行。规则在「设置 → 防盗链」里管理，仅管理员可用。

别忘了把你自己用图的站点（博客、文档站）加进去，包括需要的子域。

### 规则写法

| 写法 | 匹配 |
|---|---|
| `example.com` | 只匹配 `example.com` 本身 |
| `*.example.com` | 匹配 `example.com` 的任意子域（如 `blog.example.com`、`a.b.example.com`），不匹配 `example.com` 本身 |

- 只写主机名，不带协议、端口与路径。不区分大小写，保存时转为小写。
- 允许单段主机名（如 `localhost`）与 IPv4 地址，长度不超过 253 个字符。
- 匹配时只看 `Referer` 里的主机名，端口不参与。
- 重复添加返回 409。添加与删除都立即生效，不需要重启，并记入审计日志。
- 规则只保存在元数据库里，通过后台或[接口](../api/admin-referer.mdx)增删，没有对应的环境变量或配置文件。

### 判定规则

| 请求 | 没有规则 | 有规则 |
|---|---|---|
| 带 `Referer` | 放行 | 主机名命中任一规则才放行；`Referer` 无法解析视为未命中 |
| 不带 `Referer` | 放行 | 由「空 Referer 放行」开关决定，即配置 `allow_empty_referer`，出厂开启 |

不带 `Referer` 的常见情况：在地址栏直接打开、下载工具、设置了 `Referrer-Policy: no-referrer` 的页面。

被拒绝的请求返回 403（纯文本 `禁止访问`），不计访问。

防盗链只作用于 `/i/` 与 `/o/` 两个公开入口。管理后台里的缩略图与预览、S3 GetObject 不受影响。

<Callout type="info" title="防盗链是轻量防护">
`Referer` 可以被伪造或省略；开启「空 Referer 放行」时，不带 `Referer` 的请求都能拿到图。
图片经过 CDN 时，CDN 缓存命中的请求不会回到本机，本机的规则管不到它们，需要在 CDN 侧另配规则；redirect 模式下渠道的公开地址也不在保护范围内。
</Callout>

## 私有图片 [#private-images]

默认情况下图片链接是公开的：知道链接就能访问，短 ID 只是随机标识，不是密钥。需要限制访问的图片可以设为私有：公开链接打不开，只有带有效签名、有时效的链接能访问，且不走渠道直链、不被 CDN 缓存。见[私有图片](./private.mdx)。

不想给任何人看的内容，不要传进图床；只想限制哪些站点能嵌入，用[防盗链](#hotlink-protection)。

## 访问计数

计入访问的，是到达图片的 `/i/` 与 `/o/` GET 请求，包括 304 与 302 响应。这些请求已通过防盗链，处理参数也合法。以下请求不计入：

- HEAD 请求；
- `w` 或 `format` 不合法、返回 400 的请求；
- 被防盗链拒绝的请求；
- 后台的缩略图与预览，见下文；
- S3 GetObject。

访问先记在内存里，每隔 `activity_flush_seconds`（出厂 60 秒）批量写入数据库。同一张图在一个周期内无论被访问多少次，只加 1。所以「访问次数」是有访问的周期数，不是精确的 PV，适合看趋势与排行。

每次批量写入时还会：

- 更新「最近访问」时间；
- 摘掉待清理标记；
- 开启「访问即续期」时，顺延带有效期、尚未到期的图的到期时刻，见[生命周期与查重](./lifecycle.mdx)。

在后台可以看到：

- 图片详情里的「访问次数」与「最近访问」；
- 管理员总览的「访问次数」合计与「估算流量」，以及按访问次数排序的前 10 张「热门图片」。

估算流量按「访问次数 × 原图大小」粗算：304、302 与衍生图响应都按整张原图计，会偏高；同一周期内的重复访问只计一次，会偏低。需要精确的请求量与流量，用反向代理或 CDN 的日志，以及[监控指标](../operations/monitoring.mdx)。

### 后台浏览不计访问 [#console-browsing]

管理后台的缩略图与预览走 `/api/admin/images/<短ID>/thumb`：

- 需要登录会话，不受防盗链约束；
- 与 `/i/` 走同一条处理管线，同样支持 `w` 与 `format`；
- 不计访问次数，不更新最近访问时间，不顺延有效期，也不会把图从待清理列表里摘掉。

所以管理员翻看图片，不会干扰访问统计与冷图判定。从后台复制出去的分享链接仍是 `/i/` 地址。

## 状态码 [#status-codes]

| 状态码 | 响应 | 情况 |
|---|---|---|
| 200 | 图片 | 正常输出，或处理失败后降级输出原图 |
| 302 | 跳转到渠道的公开地址 | redirect 模式下找到了可直链的渠道 |
| 304 | 无正文 | `If-None-Match` 与当前 `ETag` 一致 |
| 400 | JSON 错误信封，错误码 `variant_params_invalid` | `w` 或 `format` 不在允许的档位里。信封格式见[上传](./upload.mdx#错误响应) |
| 403 | 纯文本 `禁止访问` | 被防盗链拒绝 |
| 404 | 纯文本 | 图片不存在、已删除或已到期 |
| 500 | 纯文本 `服务内部错误` | 查询图片元数据失败（数据库故障），可以稍后重试 |
| 503 | 纯文本 `渠道暂不可用` | 健康渠道里都没有这张图的可用副本，或全部候选渠道读取失败（后一种情况下 HEAD 仍返回 200，见下文）|

HEAD 不带正文，响应头与 GET 相同。不需要按需处理时，HEAD 不读取渠道里的对象，所以全部候选渠道读取失败时，GET 返回 503，HEAD 仍返回 200。需要按需处理时，HEAD 照常生成衍生图。
