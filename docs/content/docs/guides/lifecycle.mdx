## 有效期（TTL）

每张图可以有一个有效期，到期后自动删除。没有单独的临时目录或临时上传类型：要让图片临时存在，给它设一个短有效期即可。

有效期按三层取值，从上往下第一个有设置的生效：

| 层级 | 在哪设置 | 取值 |
|---|---|---|
| 单次上传 | 表单字段 `ttl`、URL 转存的 JSON 字段 `ttl`、后台上传弹窗的「有效期」 | 秒数；`0` 或 `never` 表示永久 |
| 用户默认 | 「用户」页 → 编辑 →「默认有效期（小时）」 | 留空表示跟随全局默认；`0` 表示永久；正数为小时数 |
| 全局默认 | 「设置 → 运行配置」的「默认有效期」`default_ttl_hours` | `0` 表示永久（出厂值）；正数为小时数 |

- 单次上传显式写 `0` 或 `never`，会覆盖用户默认与全局默认，这张图就是永久的。
- S3 上传不能逐次指定，只按用户默认与全局默认取值。
- 到期时刻在上传时算好并保存。之后修改用户默认或全局默认，不影响已有的图。
- 三层的上限都是 876000 小时（100 年），超出即拒绝。其他表示时长的运营配置（扫描间隔、删除宽限、保留期、超时等）同样以 100 年为上限，按各自的单位折算。

### 修改已有图片的有效期

未到期的图片可以在详情里修改，图片的归属用户与管理员都可以：

- 「修改有效期」→ 填天数 → 点「延长」：到期时刻变成从现在起 N 天后。这个时长也成为该图新的有效期，之后的访问续期按它顺延。
- 「设为永久」：去掉到期时刻。

## 访问即续期

「访问即续期」`ttl_renew_on_access` 出厂开启。开启时，带有效期的图每被公开访问一次，到期时刻就顺延为「这次访问被记录的时刻 + 它的有效期」。

效果是有效期变成「连续这么久没人访问才过期」：有人在用的图一直保留，没人看的图到期清理。关闭后，到期时刻固定不变。

- 只有 `/i/` 与 `/o/` 的公开访问才算。后台缩略图与预览、S3 GetObject 不算，见[后台浏览不计访问](./access.mdx#console-browsing)。
- 访问先在内存里累计，每隔 `activity_flush_seconds`（出厂 60 秒）批量写入一次，续期在写入时发生。
- 写入时已经到期的图不会续期。
- 永久的图不受影响。

## 到期清理

图一到期，对外链接就返回 404。到期是最终状态：不会再被访问续期，也不能再修改有效期（接口返回 409 `image_expired`）。在后台「图片」页，它显示为「已过期」，仍可手动删除。它的记录与文件由之后的清理扫描回收。

清理扫描在进程启动时先跑一轮，之后每隔 `cleanup_sweep_seconds`（出厂 60 秒）一轮。每轮依次：

1. 删除已到期的图，每轮最多 500 张，剩下的下一轮继续；
2. 物理删除已过宽限期的文件，见[删除流程](#delete-flow)；
3. 给冷图打待清理标记，见[冷图待清理](#cold-images)；
4. 回收超过保留期的上传幂等键；
5. 设置了「审计日志保留天数」`audit_retention_days` 时，回收过期的审计日志。出厂 0，表示永久保留。

服务停机期间到期的图，会在重启后的扫描里删除。

## 删除流程 [#delete-flow]

到期、后台删除（单张或批量，一次最多 100 张）、「待清理」页里的删除、S3 DeleteObject，都走同一条删除流程：

<Steps>
<Step>

**删除记录**：删除这条图片记录与指向它的幂等键，并把它所指物理文件的引用计数减 1。链接立即返回 404。

配置了 Cloudflare 缓存清理时，同时为 `/i/<短ID>` 及这张图生成过的衍生图参数组合排队清理 CDN 缓存。`/o/` 别名链接不在清理范围内。见 [CDN](../operations/cdn.mdx)。

</Step>
<Step>

**标记待删**：引用计数降到 0 时，物理文件被标记为待删除，删除时刻为「现在 + 删除宽限」。删除宽限 `delete_grace_minutes` 出厂为 0，即下一轮扫描就删。

</Step>
<Step>

**物理删除**：删除时刻过后的那一轮扫描先删掉它的衍生图缓存，再删除它的数据库记录，然后为每个持有副本的渠道排队删除对象。渠道删除异步执行，失败会重试；最终没删掉的对象成为无主对象，由对账回收，见[备份与恢复](../operations/backup.mdx#对账-gc)。

</Step>
</Steps>

一个物理文件可以被多条图片记录共享，这是查重合并的结果。删除其中一条不影响其他记录，最后一条引用删除后，物理文件才进入删除流程。图片详情里的「引用数」显示当前的引用计数。

后台的删除确认框会按当前的删除宽限，提示物理文件大约多久后清理。

删除用户之前，必须先删掉该用户名下的全部图片。

## 冷图待清理 [#cold-images]

长时间没人访问的图会被打上「待清理」标记，出现在后台「待清理」页，等管理员裁决。**不会自动删除**：删除不可撤销，删不删由人决定。

- **阈值**：「冷图清理阈值」`cold_cleanup_days`，出厂 90 天；设为 0 则不再打标。
- **打标**：每轮清理扫描时，最近一次公开访问早于阈值、且未被豁免的图会被打上标记。从未被访问过的图按上传时间算。
- **摘标**：以下任一情况发生时，标记被摘掉：
  - 图被公开访问，在下一次访问计数写入时摘掉；
  - 管理员设置或取消该图的清理豁免（裁决「保留」就是设置豁免）。取消豁免后，由下一轮扫描重新判定；
  - 图被删除。
- 调大阈值或把阈值设为 0，不会摘掉已有的标记。
- 冷图判定与有效期互不相关：带有效期的图同样可能被标记，被豁免的图照样会到期。

### 裁决

「待清理」页（仅管理员）按最近访问时间从早到晚列出，可以单张或批量操作：

- 「保留」：给图设上清理豁免，之后不再参与冷图打标。有效期与访问续期不受影响。豁免可以在图片详情里取消。
- 「删除」：走上面的[删除流程](#delete-flow)。

### 清理豁免

只有管理员能设置清理豁免，归属用户不能自己给图设豁免来躲开回收。

- 图片详情里的「清理豁免」开关可以在图变冷之前就打开。普通用户看得到状态，但不能修改。
- 「图片」页的筛选「仅看已豁免」列出全部已豁免的图。

## 查重 [#deduplication]

上传时不查重，上传不会因此变慢。后台查重在进程启动时先跑一轮，之后每隔 `dedup_scan_seconds`（出厂 300 秒）一轮。每轮先合并精确重复，再扫描相似重复：

| | 精确重复 | 相似重复 |
|---|---|---|
| 判定 | 实际保存的字节完全相同（SHA-256 相同）| 感知哈希的差异位数不超过阈值 |
| 处理 | 自动合并 | 进入「疑似重复」页，由管理员裁决 |

### 精确重复：自动合并

字节完全相同，合并后每个链接输出的内容都不变，所以自动进行：

- 保留其中最早的一份，其余文件的图片记录都指向它，引用计数并入；
- 多出来的文件标记待删，按删除宽限物理删除；
- 不同用户的文件同样合并。每条图片记录仍保留自己的短 ID、归属用户、有效期与访问计数，所有链接继续可用；
- 配额按引用计全额，合并不减少任何用户的已用量。

### 相似重复：人工裁决

每个物理文件上传时都会算出 64 位感知哈希（pHash）。两个文件的哈希差异位数（汉明距离）不超过「相似判定阈值」`dedup_phash_max_distance`（出厂 10）时，作为一对候选进入「疑似重复」页。

- 阈值越大越宽松，误报越多；设为 0 则不做相似扫描。后台提示：距离 0–2 基本是同一张图。
- 距离为 0 也只进候选、不自动合并：感知哈希相同不代表字节相同。
- 扫描是增量的，每轮只拿新文件与已有文件比较。进程重启后会全量重扫一次，已忽略的候选不会再出现。

### 裁决与选择保留哪一张

「疑似重复」页（仅管理员）把每对候选并排显示为左图、右图，附格式、尺寸、大小、引用数与距离，按距离从小到大排列：

- 「保留这张」→ 确认「合并」：另一张的全部引用都指向保留的这张，被合并的文件按删除宽限清理，涉及它的其他候选一并移除。**不可撤销。**
- 「忽略」：这一对以后不再提示，可以批量忽略。

合并后，被合并一方的所有链接（包括其他用户的引用）都输出保留方的内容，尺寸、格式乃至画面都可能不同。所以通常保留分辨率更高、格式更合适的一张；两张其实是不同的图片时，选「忽略」。已经缓存了旧内容的浏览器与 CDN，在缓存过期前仍显示旧图。合并不会触发 CDN 缓存清除，需要立即生效时，手动清除 CDN 缓存，见 [CDN](../operations/cdn.mdx#cloudflare-缓存清除)。

合并与忽略都记入审计日志，动作分别是「合并重复图」与「忽略重复图」。

## 相关配置

| 配置键 | 后台名称 | 出厂值 |
|---|---|---|
| `default_ttl_hours` | 默认有效期 | 0（永久）|
| `ttl_renew_on_access` | 访问即续期 | 开 |
| `cold_cleanup_days` | 冷图清理阈值 | 90 天 |
| `delete_grace_minutes` | 删除宽限 | 0 分钟 |
| `cleanup_sweep_seconds` | 清理扫描间隔 | 60 秒 |
| `activity_flush_seconds` | 访问统计写入间隔 | 60 秒 |
| `idempotency_key_ttl_hours` | 幂等键保留期 | 24 小时 |
| `dedup_scan_seconds` | 查重扫描间隔 | 300 秒 |
| `dedup_phash_max_distance` | 相似判定阈值 | 10 |
| `audit_retention_days` | 审计日志保留天数 | 0（永久）|

都在「设置 → 运行配置」修改，保存即生效，见[配置](../configuration.mdx)。
