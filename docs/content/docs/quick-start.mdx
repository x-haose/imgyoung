---
title: 快速开始
description: 用 Docker 跑起 ImgYoung，登录后台，上传第一张图并拿到 Markdown 链接。
---

需要一台装好 Docker 的机器（Linux、macOS、Windows 均可），并能用浏览器访问它的 8721 端口。不用 Docker 的安装方式见 [安装](./install/index.mdx)。

<Steps>
<Step>

### 启动服务

```bash title="终端"
docker run -d --name imgyoung --restart unless-stopped \
  -p 8721:8721 \
  -v imgyoung-data:/data \
  ghcr.io/x-haose/imgyoung:latest
```

- `-v imgyoung-data:/data`：数据库、内置 local 渠道里的图片与主密钥 `master.key` 都在这个卷里，删掉卷就是删掉全部数据。
- `--restart unless-stopped`：后台从快照恢复元数据库时，服务会主动退出、由 Docker 重新拉起后换入快照；没有重启策略，恢复后容器会停在已退出状态。

确认启动成功：

```bash title="终端"
docker logs imgyoung
```

看到 `msg="ImgYoung 已启动"` 一行即可（日志文案为中文）。首次启动还会有两条 `level=WARN`：`已生成主密钥文件,请立即备份——丢失将导致渠道配置与加密渠道数据永久不可恢复` 与 `已为内置管理员生成初始密码,请用它登录并立即修改`（行尾 `password=` 后面就是初始密码），都是预期行为。

</Step>
<Step>

### 登录并修改密码

浏览器打开 `http://<服务器地址>:8721/`（本机就是 `http://localhost:8721/`），用内置管理员登录：用户名 `admin`，密码是首次启动时随机生成的初始密码，在日志里找：

```bash title="终端"
docker logs imgyoung 2>&1 | grep 初始密码
```

`password=` 后面就是初始密码。想自己指定的话，在 `docker run` 时加上 `-e IMGYOUNG_ADMIN_PASSWORD=你的初始密码`（至少 8 个字符），日志里就不会打印它。

首次登录后会直接进入「设置管理员密码」页。改密之前，后台其他页面都打不开；服务端也只接受退出、查看本人信息与改密这几个后台接口，其余一律返回 403。

新密码至少 8 个字符，一个汉字算一个字符。点「保存并重新登录」后，用新密码再登录一次。

</Step>
<Step>

### 上传第一张图

两种方式任选其一：在后台直接上传，或者签发一个上传 Token 用 curl 上传。

<Tabs items={['后台上传', 'curl 上传']}>
<Tab value="后台上传">

1. 侧栏进入「图片」，点「上传图片」。
2. 把图片拖进对话框，或按 Ctrl / ⌘ + V 粘贴剪贴板里的截图。支持 JPEG、PNG、GIF、WebP，单图出厂上限 50 MB。
3. 上传完成后关闭对话框，点图片卡片打开「图片详情」，在「分享链接」的「复制为」里点 **Markdown**。

</Tab>
<Tab value="curl 上传">

1. 侧栏进入「上传 Token」，点「签发 Token」，用途名称填 `curl`，有效期保持「永久」，点「签发」。
2. 复制弹窗里以 `imgy_` 开头的 Token 明文。明文只展示这一次，勾选「我已妥善保存这段明文」后才能关闭弹窗。
3. 上传：

```bash title="终端"
curl -H "Authorization: Bearer imgy_你的Token" \
  -F "file=@screenshot.png" \
  http://localhost:8721/api/upload
```

```json title="响应"
{"id":"R0RjUyP1UW","url":"http://localhost:8721/i/R0RjUyP1UW"}
```

`url` 就是图片地址。装了 jq 可以直接得到 Markdown：

```bash title="终端"
curl -s -H "Authorization: Bearer imgy_你的Token" -F "file=@screenshot.png" \
  http://localhost:8721/api/upload | jq -r '"![](\(.url))"'
```

</Tab>
</Tabs>

拿到的 Markdown 形如：

```md
![](http://localhost:8721/i/R0RjUyP1UW)
```

贴进博客或笔记即可显示。

</Step>
</Steps>

<Callout type="info" title="链接里的域名从哪来">
  没有配置对外站点地址（`base_url`）时，链接按本次请求的地址生成：用 `localhost` 访问后台，复制出的就是 `localhost` 链接，别的机器打不开。
  要发给别人看，请用对外的域名或 IP 访问后台，或在「设置 → 运行配置」里填写 `base_url`。详见 [配置](./configuration.mdx)。
</Callout>

## 下一步

<Callout type="warn" title="现在所有数据都在一块盘上">
  全新实例只有一个内置的 `local` 渠道，图片存在数据卷里的 `blobs/` 目录。元数据库快照写到每个健康渠道，此刻也只有这一处。这块盘坏了，图片和快照会一起丢失，后台「总览」也会提示「数据只存在这台主机上」。

  尽快到侧栏「存储渠道」点「新建渠道」，加一个异地的对象存储或网盘渠道。已有图片会自动补齐副本到新渠道；快照会在下一轮定时备份或下次启动时写过去，想马上有一份，就到「设置 → 备份与导出」点「立即备份」。新渠道健康后，总览上的提示随之消失。
</Callout>
