## 接口文档从哪里来

仓库里的 `api/openapi.yaml`(OpenAPI 3.1)是 ImgYoung 对外 HTTP 接口的唯一依据。本节各分组页由它生成;
端到端测试用它核对每条 `/api/`、`/healthz` 与 `/i/` 响应的状态码与响应体;管理后台的前端类型也由它生成。

这份文档编译进了二进制,运行中的实例在 `GET /api/openapi.yaml` 提供与自身版本一致的副本,可以直接导入 Swagger UI、
Scalar 或各类代码生成器:

```bash title="终端"
curl -o openapi.yaml https://img.example.com/api/openapi.yaml
```

S3 协议面(`/s3/…`)按 AWS S3 规范实现,使用 XML 错误体,不在本参考内;用法见 [上传客户端](../guides/clients.mdx)。

## 认证

认证面只有两个,凭证互不通用:

| | 数据面 | 管理后台 |
|---|---|---|
| 路径 | `POST /api/upload`、`POST /api/upload/url` | `/api/admin/…` |
| 凭证 | 上传 Token,放在 `Authorization: Bearer <token>` 头 | 会话 cookie `imgyoung_session`;状态变更请求另带 `X-CSRF-Token` 头 |
| 获取方式 | 在管理后台「上传 Token」页签发,明文只显示一次 | `POST /api/admin/auth/login` |
| 认证失败 | 401:Token 无效、已过期或已吊销 | 401:未登录或会话已过期 |
| 权限不足 | 403:Token 没有上传权限 | 403:CSRF 令牌缺失或不匹配;需要管理员权限 |

上传 Token 形如 `imgy_…`,只授权数据面,管理后台的接口一律不接受它。图片访问入口(`/i/…`、`/o/…`)与 `/healthz`、
`/api/openapi.yaml` 不需要认证。

### 会话与 CSRF 令牌

<Steps>
<Step>

**登录**:`POST /api/admin/auth/login`,请求体 `{"name": "<登录名>", "password": "<密码>"}`。
成功后响应设置会话 cookie,响应体为 `{"user": {…}, "csrf_token": "…"}`。

</Step>
<Step>

**调用接口**:每个请求都带上 cookie。`GET`、`HEAD`、`OPTIONS` 只需 cookie;其余方法还要以 `X-CSRF-Token` 头回传
登录时拿到的 `csrf_token`,缺失或不匹配返回 403。

</Step>
<Step>

**恢复登录态**:页面刷新等丢失了 `csrf_token` 时,`GET /api/admin/me` 会返回当前用户与同一个 `csrf_token`。

</Step>
</Steps>

```bash title="终端"
# 登录,cookie 存进 jar.txt;记下响应体里的 csrf_token
curl -c jar.txt -H 'Content-Type: application/json' \
  -d '{"name":"admin","password":"<密码>"}' \
  https://img.example.com/api/admin/auth/login

# 读接口只需 cookie
curl -b jar.txt https://img.example.com/api/admin/me

# 状态变更接口还要带 CSRF 令牌
curl -b jar.txt -X POST -H 'X-CSRF-Token: <csrf_token>' \
  https://img.example.com/api/admin/auth/logout
```

会话的细节:

- cookie 带 `HttpOnly` 与 `SameSite=Lax`;请求经 HTTPS 到达时(直接 TLS,或受信任的反向代理以 `X-Forwarded-Proto` 告知)另带 `Secure`。
- 会话有效期 30 天,从登录时刻算起,不随使用顺延;到期后须重新登录。
- 修改密码后,该用户的全部会话失效。
- 登录尝试过于频繁时返回 429。

渠道、用户、防盗链、审计、告警、备份、导出、裁决,以及运营配置的全量读取与修改,仅管理员可用,普通用户调用返回 403。

## 错误格式

除下面的例外,错误响应一律是 JSON 信封:

```json
{ "error": "存储渠道暂不可用,请稍后重试" }
```

`error` 是面向用户的描述(中文),不含内部细节与凭证。程序据 HTTP 状态码判断错误类别,不要解析这段文字。

**例外是图片访问入口**(`/i/{id}` 与 `/o/{user_id}/{object_key}`):除了处理参数非法的 400 仍是 JSON 信封,
其余错误响应都是纯文本,例如防盗链拒绝的 403、图片不存在(包括到期后已被回收、已删除)的 404、暂无渠道可读的 503。

常见状态码:

| 状态码 | 含义 |
|---|---|
| 400 | 请求体或参数非法 |
| 401 | 未认证:Token 无效,或未登录、会话已过期 |
| 403 | 无权限:CSRF 校验失败、需要管理员、Token 无上传权限;上传时也表示存储配额已满 |
| 404 | 目标不存在,或对当前用户不可见 |
| 409 | 与现有状态冲突,如重名,或渠道持有部分图片的唯一副本 |
| 413 | 超过单图大小上限(运营配置 `max_upload_mb`) |
| 415 | 不是支持的图片格式(按文件内容判定) |
| 422 | 分辨率超出像素预算(运营配置 `max_pixels_mp`) |
| 429 | 上传并发已满、该用户上传过于频繁,或登录尝试过于频繁;有 `Retry-After` 头时按它等待 |
| 503 | 上传时没有健康渠道可写或同步副本数不足;访问图片时暂无渠道能读出 |

每个接口实际可能返回的状态码,以各分组页为准。

## 通用约定

- **时刻**:除特别说明外,均为 UTC 文本 `YYYY-MM-DD HH:MM:SS`(如 `2026-10-15 08:30:00`),不带时区后缀。
  例外是构建信息的 `built_at` 与备份快照的 `taken_at`,为 RFC 3339。
- **列表**:列表接口返回 `{"items": […], "total": N}`,`total` 是过滤后的总条数。
- **分页**:图片、上传 Token、疑似重复、待清理、审计日志、告警列表支持 `page`(从 1 起,默认 1)与 `page_size`(默认 20,
  最大 100,超出按 100 处理)。
- **时间范围**:图片列表与审计日志支持 `since`(含)与 `until`(不含),格式同上。
- **ID**:图片为 10 位短 ID 字符串;用户 ID 为字符串(内置管理员为 `default`);Token、渠道、疑似重复候选等记录为整数;备份快照以文件名标识。
- **幂等上传**:上传请求可带 `Idempotency-Key` 头,保留期(运营配置 `idempotency_key_ttl_hours`,默认 24 小时)内,
  同一用户同一键的重试返回同一张图。键按用户隔离。
- **请求体**:JSON 接口使用 `application/json`;文件上传使用 `multipart/form-data`,文件字段名为 `file`。
- **服务地址**:接口与站点同源,路径前缀即上文所列,没有版本号段。
