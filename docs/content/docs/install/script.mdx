## 用法

```bash title="终端"
curl -fsSL https://raw.githubusercontent.com/x-haose/imgyoung/main/install.sh | sh
```

选项经 `sh -s --` 传给脚本：

```bash title="终端"
# 装成 systemd 服务并启动(仅 Linux,需要 root)
curl -fsSL https://raw.githubusercontent.com/x-haose/imgyoung/main/install.sh | sudo sh -s -- --service

# 安装指定版本
curl -fsSL https://raw.githubusercontent.com/x-haose/imgyoung/main/install.sh | sh -s -- --version 1.0.0
```

想先读一遍脚本再执行：

```bash title="终端"
curl -fsSLo install.sh https://raw.githubusercontent.com/x-haose/imgyoung/main/install.sh
less install.sh
sudo sh install.sh --service
```

脚本需要 `curl`、`tar`、`install`，以及 `sha256sum` 或 `shasum` 之一；加 `--service` 时还需要 `systemctl`。

## 选项与环境变量

| 选项 | 默认 | 说明 |
|---|---|---|
| `--version X.Y.Z` | 最新正式版 | 安装指定版本 |
| `--dir DIR` | root 为 `/usr/local/bin`，其他用户为 `~/.local/bin` | 二进制的安装目录 |
| `--service` | 不安装服务 | 同时安装并启动 systemd 服务 `imgyoung`，数据在 `/var/lib/imgyoung`。仅 Linux，需要 root |

- `--version` 须形如 `1.2.3` 或 `1.2.3-rc.1`，前缀 `v` 可带可不带。
- `--dir` 不存在时会创建，且必须可写。与 `--service` 同用时，须为绝对路径，且不能在 `/home`、`/root`、`/run/user` 下，原因见下文「systemd 服务」。

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `IMGYOUNG_RELEASES` | `https://github.com/x-haose/imgyoung/releases` | 发布页地址。使用镜像站或内网分发时设置，见下文「镜像站与内网分发」 |

选项无法识别或版本号格式不对时，脚本立即报错退出，不做任何改动。报错原文见页末[报错信息](#报错信息)。

## 脚本做了什么

1. **检查前提**：确认 `curl`、`tar`、`install` 存在。带 `--service` 时，还确认系统是 Linux、以 root 运行、有 `systemctl`，以及指定的 `--dir` 是家目录之外的绝对路径。不满足就在下载之前退出，不改动系统。
2. **识别平台**：`uname -s` 须为 `Linux` 或 `Darwin`，`uname -m` 须为 `x86_64`、`amd64`、`aarch64` 或 `arm64`，其他系统或架构直接报错。Windows 请用[发布包](./binary.mdx)。
3. **确定版本**：没有指定 `--version` 时，请求 `<发布页>/latest` 并跟随跳转，取最终地址的最后一段作为版本号，按与 `--version` 相同的格式校验。GitHub 的 latest 不会指向预发布版。
4. **下载并校验**：把 `imgyoung_<版本号>_<系统>_<架构>.tar.gz` 与同版本的 `checksums.txt` 下载到临时目录，核对 sha256。不一致即中止，不安装任何东西。临时目录在脚本退出时删除。
5. **安装二进制**：以 0755 权限装为目标目录下的 `imgyoung`，并打印它的版本信息。
6. **安装服务**（仅 `--service`）：把发布包里的 `deploy/imgyoung.service` 写到 `/etc/systemd/system/imgyoung.service`，其中 `ExecStart` 换成实际安装路径；与原有文件内容不同时给出提示。然后执行 `systemctl daemon-reload` 并启用服务。服务已在运行就重启它以换上新版本，否则启动它。
7. **提示下一步**：目标目录不在 `PATH` 中时给出提醒，并打印登录地址与出厂账号。

没加 `--service` 时，脚本只安装二进制，不会启动它。直接运行 `imgyoung` 即可，数据写在当前目录的 `data/`，可用 `IMGYOUNG_DATA_DIR` 指定。长期运行请交给进程管理器，原因见[安装方式](./index.mdx)。

## systemd 服务

`--service` 安装的就是仓库里的这份示例，只改了 `ExecStart`：

<include cwd lang="ini" meta='title="deploy/imgyoung.service"'>../deploy/imgyoung.service</include>

主要设置：

| 设置 | 作用 |
|---|---|
| `IMGYOUNG_DATA_DIR=%S/imgyoung`、`StateDirectory=imgyoung` | 数据目录为 `/var/lib/imgyoung`，由 systemd 创建并交给运行用户 |
| `DynamicUser=yes` | 每次启动由 systemd 分配一个临时系统用户来运行，不需要预先创建用户 |
| `Restart=always` | 进程退出后 3 秒重新启动，包括正常退出 |
| `TimeoutStopSec=15s` | 停止服务时最多等待 15 秒 |
| `UMask=0077` | 新建的文件（包括 `master.key`）只有运行用户可读写 |
| `RCLONE_CONFIG=`（置空）| ImgYoung 直接把渠道参数交给 rclone，不读 rclone 的配置文件 |
| `ProtectSystem=strict`、`ProtectHome=yes` 等 | 进程只能写自己的数据目录，也看不到家目录 |

需要注意的几点：

- **数据目录的实际位置**：启用 `DynamicUser` 时，实际目录是 `/var/lib/private/imgyoung`，`/var/lib/imgyoung` 是指向它的符号链接。里面是 `imgyoung.db`、`master.key`、local 渠道的 `blobs/` 与衍生图缓存 `variants/`。
- **沙箱限制**：local 渠道的路径改到数据目录之外时，要用 `ReadWritePaths=` 放开那个目录。二进制不能装在 `/home` 或 `/root` 下，否则服务无法启动，所以脚本会拒绝这样的 `--dir`。
- **为什么是 `Restart=always`**：在后台恢复快照时，服务会正常退出，systemd 重新启动它时才换入快照。`Restart=on-failure` 不会重启正常退出的进程，恢复要等有人手动启动服务才能完成。
- **停止时间**：停止时，服务先停止接收新请求并等在途请求结束，再停下后台任务、关闭数据库，全程最多约 8 秒，15 秒留有余量。停止时中断的补齐任务（把图片复制到其他渠道的后台任务）会在下次启动后重新排队。

常用命令：

```bash title="终端"
systemctl status imgyoung        # 运行状态
journalctl -u imgyoung -f        # 跟踪日志
sudo systemctl restart imgyoung  # 改了环境变量后重启生效
```

### 修改服务配置

带 `--service` 重新执行脚本时，`/etc/systemd/system/imgyoung.service` 会被发布包里的版本整个覆盖，内容有变化时脚本会提示。本机的改动不要写进这个文件，而是写进 drop-in：

```bash title="终端"
sudo systemctl edit imgyoung
```

在打开的编辑器里写入要覆盖的设置。例如只经本机反向代理对外时，改成只监听回环地址：

```ini title="/etc/systemd/system/imgyoung.service.d/override.conf"
[Service]
Environment=IMGYOUNG_LISTEN=127.0.0.1:8721
```

保存后执行 `sudo systemctl restart imgyoung`。可用的环境变量见[配置](../configuration.mdx)。

## 升级

重新执行安装时用的同一条命令：

- **安装时加了 `--service`**：脚本替换二进制、重写服务文件，并重启服务换上新版本。升级时必须同样带上 `--service`，否则只替换了磁盘上的文件，运行中的仍是旧版本。
- **没加 `--service`**：脚本只替换二进制，需要自己重启进程。

数据库结构在新版本启动时自动迁移。要停留在某个版本，用 `--version` 指定。

`--version` 也能装回旧版本，但不能借此降级：旧版本会拒绝启动被新版本迁移过的数据库，并在错误信息里写明数据库与二进制各自的最新迁移版本。回滚要用旧版本加上升级前的快照，步骤与升级前的准备见[升级](../operations/upgrade.mdx)。

## 卸载

装了服务时：

```bash title="终端"
sudo systemctl disable --now imgyoung
sudo rm /etc/systemd/system/imgyoung.service
sudo rm -rf /etc/systemd/system/imgyoung.service.d   # 用过 systemctl edit 才有
sudo systemctl daemon-reload
sudo rm /usr/local/bin/imgyoung
```

数据目录不会随之删除。确认已经不需要其中的图片、数据库与 `master.key` 之后再删除：

```bash title="终端"
sudo rm -rf /var/lib/private/imgyoung /var/lib/imgyoung
```

只装了二进制时，删除二进制（默认为 `~/.local/bin/imgyoung` 或 `/usr/local/bin/imgyoung`），再按需删除运行时用过的数据目录。

## 镜像站与内网分发

访问 GitHub 不便时，把发布文件放到镜像站或内网服务器上，用 `IMGYOUNG_RELEASES` 指向它。这个环境变量要传给执行脚本的 `sh`，而不是 `curl`：

```bash title="终端"
curl -fsSL https://mirror.example.com/imgyoung/install.sh \
  | sudo IMGYOUNG_RELEASES=https://mirror.example.com/imgyoung/releases sh -s -- --service
```

`install.sh` 本身也要能从那里下载。镜像站的目录结构须与 GitHub Releases 一致：

```text
<IMGYOUNG_RELEASES>/latest                                   跳转到 .../tag/vX.Y.Z
<IMGYOUNG_RELEASES>/download/vX.Y.Z/imgyoung_X.Y.Z_linux_amd64.tar.gz
<IMGYOUNG_RELEASES>/download/vX.Y.Z/checksums.txt
```

只有不指定 `--version` 时才会用到 `/latest`：脚本跟随跳转，把最终地址的最后一段当作版本号，它须形如 `v1.2.3` 或 `v1.2.3-rc.1`。镜像站做不到这种跳转时，安装与升级都显式带上 `--version`。

## 报错信息

出错时，脚本打印一行以 `错误:` 开头的信息并退出；`tar`、`systemctl` 这类命令失败时，它们自己的报错会先打印出来。下表这几种都发生在安装之前，系统不会被改动：

| 报错 | 原因 |
|---|---|
| `错误:未知选项 <选项>` | 传入了脚本不支持的选项 |
| `错误:版本号 1.0 无效,应形如 1.0.0` | `--version` 的格式不对 |
| `错误:无法从 <最终地址> 解析出版本号;可用 --version 指定` | 没有指定 `--version`，而 `<发布页>/latest` 没有跳转到以 `vX.Y.Z` 结尾的地址 |
| `错误:<文件名> 的 sha256 不符(期望 …,实际 …),已中止` | 下载的文件与 `checksums.txt` 不一致 |
| `错误:--service 的二进制不能装在 <目录>:服务启用了 ProtectHome,进程看不到家目录` | 加了 `--service`，而 `--dir` 在家目录下 |
| `错误:<目录> 不可写;用 sudo 执行,或用 --dir 指定一个可写目录` | 安装目录没有写权限 |
| `错误:解包 <文件名> 失败` | 下载的发布包无法解开 |

下表这几种发生在安装过程中，二进制或服务可能已经部分更新。排除原因后重新运行脚本即可：

| 报错 | 原因 |
|---|---|
| `错误:无法写入 <目录>/imgyoung` | 二进制写不进安装目录，如磁盘已满 |
| `错误:<目录>/imgyoung 无法运行,检查系统与架构是否与发布包一致` | 装好的二进制无法执行，如架构不符或目录所在分区禁止执行 |
| `错误:生成服务文件失败` / `错误:无法写入 /etc/systemd/system/imgyoung.service` | 服务文件生成或写入失败 |
| `错误:systemctl daemon-reload 失败` / `错误:无法设置服务 imgyoung 开机启动` | systemd 重新加载或设置开机启动失败 |
| `错误:服务 imgyoung 启动失败,用 journalctl -u imgyoung 查看原因` / `错误:服务 imgyoung 重启失败,…` | 服务没能启动，原因见 `journalctl -u imgyoung` |
