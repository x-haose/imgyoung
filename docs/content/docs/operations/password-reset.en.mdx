title: Forgotten password
description: Recover the built-in administrator by clearing its password hash and restarting to get a new initial password, reset other users' passwords, and change your own.

## Built-in administrator forgot the password

Passwords are stored as argon2id hashes, so you cannot simply set a new password in the database. However, when the built-in administrator has no password, the service gives it an initial password at startup and requires a change after signing in: the value of the `IMGYOUNG_ADMIN_PASSWORD` environment variable if set, otherwise a random password printed in the log. Clearing its password hash and restarting therefore brings you back to the first sign-in.

There is no dedicated reset command; one SQL statement does the job. It requires a shell on the server or access to the database, so it cannot be done remotely.

The built-in administrator's ID in the `users` table is always `default`. Its username can be changed in the admin console, so the commands below select it by ID rather than by username.

<Callout type="warn">
From the restart until you change the password, anyone who can read the log (or `IMGYOUNG_ADMIN_PASSWORD` in the deployment settings) can sign in with the initial password. Sign in and change it right after the restart.
</Callout>

<Steps>
<Step>

**Clear the password hash and restart**:

<Tabs items={['Binary', 'Docker', 'Compose', 'systemd']}>
<Tab value="Binary">

Requires `sqlite3` on the machine. Stop the `imgyoung` process, then run this against the database in the data directory (`data/` under the directory you start it from, or the directory set by `IMGYOUNG_DATA_DIR`):

```bash title="Terminal"
sqlite3 data/imgyoung.db "UPDATE users SET password_hash = '' WHERE id = 'default';"
```

Then start `imgyoung` again.

</Tab>
<Tab value="Docker">

The image has neither a shell nor `sqlite3`. Run a throwaway Alpine container on the same volume, and hand the database files back to the image's runtime user afterwards:

```bash title="Terminal"
docker stop imgyoung
docker run --rm -i --volumes-from imgyoung alpine:3.24 sh -c \
  'apk add -q sqlite && sqlite3 /data/imgyoung.db && chown 65532:65532 /data/imgyoung.db*' <<'SQL'
UPDATE users SET password_hash = '' WHERE id = 'default';
SQL
docker start imgyoung
```

Replace `imgyoung` with your container name.

</Tab>
<Tab value="Compose">

From the directory containing `compose.yaml`:

```bash title="Terminal"
docker compose stop imgyoung
docker run --rm -i --volumes-from "$(docker compose ps -a -q imgyoung)" alpine:3.24 sh -c \
  'apk add -q sqlite && sqlite3 /data/imgyoung.db && chown 65532:65532 /data/imgyoung.db*' <<'SQL'
UPDATE users SET password_hash = '' WHERE id = 'default';
SQL
docker compose start imgyoung
```

</Tab>
<Tab value="systemd">

The data directory is `/var/lib/imgyoung`; requires `sqlite3` on the machine:

```bash title="Terminal"
sudo systemctl stop imgyoung
sudo sqlite3 /var/lib/imgyoung/imgyoung.db "UPDATE users SET password_hash = '' WHERE id = 'default';"
sudo systemctl start imgyoung
```

</Tab>
</Tabs>

</Step>
<Step>

**Check that the initial password was set**: the startup log shows `已为内置管理员生成初始密码,请用它登录并立即修改`, and the initial password follows `password=`. With `IMGYOUNG_ADMIN_PASSWORD` set, the line is `已按 IMGYOUNG_ADMIN_PASSWORD 设置内置管理员的初始密码,请登录后立即修改` instead.

</Step>
<Step>

**Sign in and change the password**: sign in with the built-in administrator's username (`admin` unless you renamed it) and the initial password. You land directly on **Set the admin password**. After changing it, sign in again with the new password.

</Step>
</Steps>

Until the initial password is changed, that session can only sign out, read its own account (`GET /api/admin/me`) and change the password. Every other admin API returns 403 with error code `must_change_password`, and the same applies to scripts calling the API directly.

This only works for the built-in administrator. Clearing another user's `password_hash` just makes that account unable to sign in; no password is restored. Reset other users' passwords as described in the next section.

## Resetting another user's password

Administrators can reset any user's password in the admin console, including another administrator's: on **Users**, open the **More actions** menu at the end of the user's row, choose **Reset password**, and enter the new password.

- The new password must be at least 8 characters, counted as characters rather than bytes, so a Chinese character counts as one.
- The reset takes effect immediately and ends all of that user's sessions; they sign in again with the new password.
- The user is not required to change a reset password after signing in.
- Each reset writes an audit entry (action `user.update`, detail `password.reset`).

For the API, see the [API reference](../api/admin-users.mdx).

## Changing your own password

Users who know their current password can change it themselves with **Change password** in the account menu in the sidebar; the same length rule applies. The API is `PUT /api/admin/me/password`; see the [API reference](../api/admin-session.mdx).
