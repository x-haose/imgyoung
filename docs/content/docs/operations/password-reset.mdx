## 内置管理员忘记密码

密码以 argon2id 哈希保存，不能直接在数据库里改成某个密码。但内置管理员没有密码时，服务启动会为它设置初始密码，并要求登录后修改：设置了环境变量 `IMGYOUNG_ADMIN_PASSWORD` 时用它，否则随机生成一个并打印在日志里。因此，清空它的密码哈希再重启，就回到了首次登录时的状态。

没有专门的重置命令，用一条 SQL 完成。这需要服务器的 shell 或数据库的访问权限，无法远程操作。

内置管理员在 `users` 表里的 ID 固定为 `default`。登录名可以在后台修改，所以下面的命令按 ID 定位，而不是按登录名。

<Callout type="warn">
重启后到你改掉密码之前，能读到日志（或部署配置里的 `IMGYOUNG_ADMIN_PASSWORD`）的人都能用初始密码登录。重启后请立即登录修改。
</Callout>

<Steps>
<Step>

**清空密码哈希并重启**：

<Tabs items={['二进制', 'Docker', 'Compose', 'systemd']}>
<Tab value="二进制">

需要本机装有 `sqlite3`。先停止 `imgyoung` 进程，对数据目录（默认是启动目录下的 `data/`，或 `IMGYOUNG_DATA_DIR` 指定的目录）里的数据库执行：

```bash title="终端"
sqlite3 data/imgyoung.db "UPDATE users SET password_hash = '' WHERE id = 'default';"
```

然后重新启动 `imgyoung`。

</Tab>
<Tab value="Docker">

镜像里没有 shell 和 `sqlite3`。借一个临时的 Alpine 容器挂上同一个数据卷执行，结束后把数据库文件的属主改回镜像的运行用户：

```bash title="终端"
docker stop imgyoung
docker run --rm -i --volumes-from imgyoung alpine:3.24 sh -c \
  'apk add -q sqlite && sqlite3 /data/imgyoung.db && chown 65532:65532 /data/imgyoung.db*' <<'SQL'
UPDATE users SET password_hash = '' WHERE id = 'default';
SQL
docker start imgyoung
```

把 `imgyoung` 换成你的容器名。

</Tab>
<Tab value="Compose">

在 `compose.yaml` 所在目录执行：

```bash title="终端"
docker compose stop imgyoung
docker run --rm -i --volumes-from "$(docker compose ps -a -q imgyoung)" alpine:3.24 sh -c \
  'apk add -q sqlite && sqlite3 /data/imgyoung.db && chown 65532:65532 /data/imgyoung.db*' <<'SQL'
UPDATE users SET password_hash = '' WHERE id = 'default';
SQL
docker compose start imgyoung
```

</Tab>
<Tab value="systemd">

数据目录是 `/var/lib/imgyoung`，需要本机装有 `sqlite3`：

```bash title="终端"
sudo systemctl stop imgyoung
sudo sqlite3 /var/lib/imgyoung/imgyoung.db "UPDATE users SET password_hash = '' WHERE id = 'default';"
sudo systemctl start imgyoung
```

</Tab>
</Tabs>

</Step>
<Step>

**确认初始密码已设置**：启动日志里出现 `已为内置管理员生成初始密码,请用它登录并立即修改`，`password=` 后面就是初始密码。设置了 `IMGYOUNG_ADMIN_PASSWORD` 时，出现的是 `已按 IMGYOUNG_ADMIN_PASSWORD 设置内置管理员的初始密码,请登录后立即修改`。

</Step>
<Step>

**登录并修改密码**：用内置管理员的登录名（默认 `admin`）和初始密码登录，页面会直接进入「设置管理员密码」。修改后，用新密码重新登录。

</Step>
</Steps>

改掉初始密码之前，这个会话只能退出登录、查看自己的账号（`GET /api/admin/me`）和修改密码。其他后台接口一律返回 403，错误码 `must_change_password`，直接用脚本调用接口也是如此。

这个办法只对内置管理员有效。清空其他用户的 `password_hash` 只会让账号无法登录，不会恢复任何密码；其他用户的密码请按下一节重置。

## 为其他用户重置密码

管理员可以在后台为任何用户重置密码，包括其他管理员：在「用户」页该用户所在行的末尾打开「更多操作」菜单，选「重置密码」，输入新密码。

- 新密码至少 8 个字符，按字符计算，一个汉字算一个字符。
- 重置立即生效，该用户的所有会话随即失效，需要用新密码重新登录。
- 重置后不要求用户再修改密码。
- 每次重置记一条审计日志（动作 `user.update`，详情 `password.reset`）。

对应的接口见[接口参考](../api/admin-users.mdx)。

## 修改自己的密码

记得旧密码的用户，可以在侧栏的账号菜单里选「修改密码」自行修改，长度要求同上。对应的接口是 `PUT /api/admin/me/password`，见[接口参考](../api/admin-session.mdx)。
