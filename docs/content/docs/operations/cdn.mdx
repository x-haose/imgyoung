## 推荐做法：proxy 模式加 CDN

让 CDN 回源到 ImgYoung（经过[反向代理](./reverse-proxy.mdx)），访问模式保持 `proxy`。这样：

- 图片由 ImgYoung 从渠道读出，某个渠道故障时，回源请求会立即换到其他渠道，CDN 看到的始终是一个稳定的源站；
- 按需处理（`?w=`、`?format=`）与 WebP 协商照常工作，处理结果由 CDN 缓存。

然后完成以下配置：

1. **对外站点地址**：对外域名是 CDN 的域名，把它填进后台「设置 → 运行配置 → 访问与链接 → 对外站点地址」（`base_url`）。
2. **信任的代理**：把 CDN 的回源网段加进 `IMGYOUNG_TRUSTED_PROXIES`，登录限速才能按真实访客计算。使用文档自带的 Caddy 示例时，还要在 Caddy 里把这些网段设为 `trusted_proxies`。见[反向代理与 HTTPS](./reverse-proxy.mdx)。
3. **缓存范围**：只缓存图片地址 `/i/*` 与 `/o/*`，`/api/*`、`/s3/*` 设为不缓存。后台页面按 CDN 的默认规则处理即可：`index.html` 带 `no-cache`，`/assets/` 下的文件名带内容哈希，并带一年强缓存。
4. **缓存键**：按 `Accept` 区分缓存，查询串只保留 `w` 和 `format`，见下文[WebP 协商与 Vary](#webp-协商与-vary)和[处理参数与缓存键](#处理参数与缓存键)。

## 缓存头

图片地址的响应头如下：

| 响应 | `Cache-Control` | `ETag` | `Vary` |
|---|---|---|---|
| `/i/<短ID>` 的原图 | `public, max-age=31536000, immutable` | `"<sha256>"` | 不带 `format`（或 `format=auto`）访问 JPEG、PNG、WebP 时为 `Accept` |
| `/i/<短ID>` 的衍生图（缩放或转格式）| 同上 | `"<sha256>-<宽度>-<格式>"`，不缩放时宽度为 `0` | 目标格式由协商决定时为 `Accept` |
| `/o/` 地址的原图与衍生图 | `public, no-cache` | 同上 | 同上 |
| 按需处理失败时改为返回的原图 | `no-store` | 无 | 无 |
| `If-None-Match` 命中（304）| 与对应的 200 响应相同 | 相同 | 相同 |
| 302（`redirect` 模式）| `no-store` | 无 | 无 |
| 参数非法（400）、防盗链拒绝（403）、不存在或已到期（404）、查询元数据失败（500，可重试）、没有渠道能读出这张图（503）| 无 | 无 | 无 |

原图响应另带 `Last-Modified`，值为上传时刻。

`/i/<短ID>` 对应的原图不会改变，所以缓存一年。唯一的例外是管理员在「疑似重复」里合并两张图：被合并一方的短 ID 从此返回保留的那张图。合并不会触发缓存清除，CDN 与浏览器在缓存期内（最长一年）仍会返回合并前的图片。需要立即生效时，在 CDN 上手动清除这条地址。见[生命周期与查重](../guides/lifecycle.mdx#deduplication)。

修改「目标格式」后，`/i/` 链接在 CDN 与浏览器里已缓存的衍生图和协商结果不会随之更新，要等缓存过期，或在 CDN 上手动清除；`/o/` 链接下次回源确认时就会拿到新的格式。只改编码参数（「WebP 质量档」「JPEG 质量档」「WebP 速度权衡」）时，两种链接已缓存的内容都不会更新：衍生图的 ETag 只由原图、宽度和格式决定，回源确认得到的仍是 304，要在 CDN 上手动清除。

`/o/<用户 ID>/<对象键>` 是 S3 客户端按自己的对象键访问的地址。同一对象键重新上传后，它会指向新图，所以响应允许缓存，但每次使用前都要带 ETag 回源确认：内容没变返回 304，指向了新图就返回新图，图片删除后返回 404。经 CDN 对外分享时，`/i/` 链接的缓存效果更好。

## WebP 协商与 Vary

不带 `format` 参数（或 `format=auto`）访问 JPEG、PNG 图片时：

- 请求头 `Accept` 含 `image/webp`，且「目标格式」里有 `webp`：返回 WebP 衍生图；
- 否则返回原格式。

因此，**同一个 URL 会按 `Accept` 返回不同格式**。这些响应（包括 304）都带 `Vary: Accept`。

CDN 必须按 `Accept` 分别缓存：遵守 `Vary: Accept`，或者把 `Accept` 加进缓存键。否则先缓存下来的 WebP 会发给不支持 WebP 的客户端。Cloudflare 可以在 Cache Rules 中配置对 `Vary` 的处理，其他 CDN 请查阅各自的文档。

CDN 做不到时，在后台「设置 → 运行配置 → 按需处理 → 目标格式」里去掉 `webp`。这样就不再协商，但 `?format=webp` 也会返回 400。

## 处理参数与缓存键

- **参数校验**：`w` 必须是「宽度档」之一，`format` 必须是「目标格式」之一或 `auto`，否则返回 400。这项检查先于其他处理，与原图格式无关：GIF 等不做处理的原图，带档位以外的参数同样返回 400，带合法参数则返回原图。
- **唯一写法**：宽度只接受规范写法，不带前导零和正负号（`?w=0400` 返回 400）；`w` 与 `format` 各最多出现一次（`?w=400&w=1` 返回 400）。每个宽度档、每种目标格式都只有一种写法，一张图的衍生图种类因此是有限的。
- **其他查询参数**：ImgYoung 忽略它们，但 CDN 默认会把它们算进缓存键，随便加一个参数就能绕过缓存直接回源。请把缓存键的查询串限定为 `w` 和 `format`。
- **参数顺序**：固定写成 `?w=…&format=…`。缓存清除只清除这个顺序的 URL（见下节），顺序不同的 URL 在 CDN 上是另一条缓存。

## Cloudflare 缓存清除

图片删除后，CDN 边缘节点仍会在一年的缓存期内继续提供它的 `/i/` 链接。配置 Cloudflare 缓存清除后，ImgYoung 在删除图片时清除这些缓存。

在后台「设置 → 运行配置」中填写三项：

| 配置 | 所在分组 | 说明 |
|---|---|---|
| Cloudflare Zone ID | 「CDN 缓存清理」| 站点所在 Zone 的 ID |
| Cloudflare API Token | 「CDN 缓存清理」| 需要该 Zone 的 Cache Purge 权限。用主密钥加密保存，保存后不再显示 |
| 对外站点地址（`base_url`）| 「访问与链接」| 用来拼出要清除的公开 URL，必须与 CDN 上的域名一致 |

三项都填写后，分组标题旁显示「已启用」；缺少任何一项时显示「未启用」，不会清除。配置保存后立即生效，不需要重启。服务启动时也会在日志里记录是否已启用。

清除规则如下：

| 项目 | 说明 |
|---|---|
| 何时清除 | 一条图片记录被删除时立即清除，不论是后台删除（单张或批量）、S3 兼容接口的 `DeleteObject`，还是有效期到期。不等删除宽限期，也不等渠道上的对象真正删除 |
| 清除哪些 URL | `<base_url>/i/<短ID>`，加上这张图实际生成过的每个衍生图的 URL：缩放过的衍生图清除 `?w=<宽度>` 与 `?w=<宽度>&format=<格式>`，只转格式的清除 `?format=<格式>` |
| 如何执行 | 后台任务异步调用 Cloudflare 按 URL 清除缓存的接口 `POST /zones/<Zone ID>/purge_cache`，每次最多 100 个 URL。失败会自动退避重试，不影响删除本身 |
| 不清除的情况 | `format=auto`、带其他查询参数或参数顺序不同的 URL，只能等 CDN 缓存自然过期。合并重复图不触发清除。`/o/` 链接每次都回源确认，不需要清除 |

## redirect 模式（302 直链）与 CDN

访问模式为 `redirect` 时，原图请求会被 302 到一个允许直链、未加密且填写了公开地址的渠道。图片由渠道（或渠道自己的域名、CDN）直接提供，不经过你放在 ImgYoung 前面的 CDN。没有这样的渠道时，按 `proxy` 模式返回。

- 302 响应一律带 `Cache-Control: no-store`，CDN 与浏览器都不缓存重定向本身。每次访问都回到 ImgYoung，渠道切换、图片删除与到期都立即生效。
- 需要生成衍生图的请求（缩放、转成另一种格式，或经协商转为 WebP）由 ImgYoung 处理后直接返回，不做 302。结果仍是原图的请求照常 302，例如 GIF 原图，或目标格式与原图相同且不缩放（JPEG 带 `?format=jpeg`）。
- 浏览器的请求通常带 `image/webp`，JPEG、PNG 会被协商成 WebP 衍生图，因此不走 302。要让浏览器访问原图也走 302，需要从「目标格式」里去掉 `webp`。

已经在 ImgYoung 前面放了 CDN 时，用 `proxy` 模式即可，流量已经由 CDN 承担。`redirect` 适合以下情况：

- 服务器前面没有 CDN，且上行带宽小；
- 渠道自带公开的 CDN 域名，如对象存储绑定的自定义域名。

## CDN 后的防盗链

ImgYoung 的 Referer 白名单只对回源请求生效：

- 命中 CDN 缓存的请求不会回源，也就不受白名单约束。缓存键默认不含 Referer，一张图被白名单内的站点访问并缓存后，任何来源都能从 CDN 拿到它。
- ImgYoung 拒绝访问时返回的 403 不带 `Cache-Control`。如果 CDN 缓存了这个 403，白名单内的访问也会被拒绝。

因此，经 CDN 对外时，请在 CDN 上配置按 Referer 拦截的规则，ImgYoung 的白名单留空或只作补充。`redirect` 模式下渠道直链直接暴露在外，白名单同样不起作用。
